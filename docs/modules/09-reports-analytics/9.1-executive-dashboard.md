# 9.1 Executive Dashboard

> Real-time business pulse for owners and branch managers. Part of [Module 9: Reports & Analytics](../09-reports-analytics.md).

## Purpose

The Executive Dashboard is the first screen an owner or branch manager opens every morning. It compresses the state of the whole business — sales, debtors, stock value, workshop load — into one page of KPI tiles and trend charts, so the manager knows within thirty seconds whether today needs intervention: are we behind target, is overdue AR climbing, are job cards piling up?

It deliberately trades depth for immediacy. Every tile is a real-time calculation (not a pre-aggregated cache) and every chart links through to the detailed report that explains it — the dashboard raises the question, the module reports answer it.

Branch scoping is fundamental: an owner sees the consolidated business and the branch comparison chart; a branch manager sees only their branch, enforced by the same branch permissions used across the reporting module.

## User Roles & Permissions

| Role | Access |
|------|--------|
| Super Admin / Owner | All branches, all tiles including financials |
| Branch Manager | Own branch only; all tiles |
| Sales Manager | Sales tiles and charts; AR tiles hidden unless granted |
| Accountant | Financial tiles (AR, stock value) across branches |
| Reports Only | View per assigned branch scope |
| Cashier / Warehouse / Technician | No access |

## Workflow

```
[Login] → [Dashboard loads with branch scope applied]
              │
              ▼
   [KPI tiles compute real-time] ──► [Anomaly spotted, e.g. Overdue AR up]
              │                                  │
              ▼                                  ▼
   [Charts render (Recharts,          [Click tile → drill into the
    Inertia props)]                    underlying report, e.g.
              │                        AR Ageing (9.4/9.5)]
              ▼
   [Refresh on page focus via Inertia partial reload]
```

1. **Load** — controller computes KPIs server-side for the user's branch scope and passes them as Inertia props.
2. **Scan** — top row of eight tiles: Today's Sales, Yesterday's Sales, MTD Sales, MTD vs Target %, Outstanding AR, Overdue AR (60+), Stock Value, Open Job Cards.
3. **Compare** — charts: 12-month sales trend (this year vs last), top 10 parts by value, sales by category donut, AR ageing stacked bar, branch comparison (multi-branch users only).
4. **Drill** — each tile/chart segment links to its source report with filters pre-applied.
5. **Refresh** — data re-fetches on window focus; no manual refresh needed through the day.

## Screens

| Screen | Route | Purpose |
|--------|-------|---------|
| Executive dashboard | `reports.dashboard` | The KPI + charts page (`Reports/Dashboard.jsx`) |

**Layout**: KPI tile row (2×4 grid on desktop, stacked on mobile) at top; below, a two-column chart area — sales trend full-width, then top-10 parts and category donut side by side, then AR ageing and branch comparison. Each tile shows the value, a small delta vs the comparison period, and a subdued caption of the period.

## Fields & Validation

The dashboard has no data-entry form. Its one configurable input is the branch selector (visible only to multi-branch users):

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| branch | select | No | limited to branches the user is permitted; "All branches" only for consolidated roles |

Sales targets feeding "MTD vs Target" are configured elsewhere (sales budget setup); the tile validates that a budget exists for the current month before rendering a percentage.

## Business Rules

1. All KPI figures are computed real-time from source tables — no pre-aggregated caches — so the dashboard always reconciles to the detailed reports.
2. Branch permissions are enforced server-side; a branch manager's requests for other-branch data return 403, not empty data.
3. "MTD vs Target" renders as "No target set" (with a setup link for admins) when no sales budget exists for the month — never as 0% or a misleading blank.
4. Today's/Yesterday's Sales count *invoiced* revenue (excl. VAT) — quotes and unposted drafts are excluded.
5. Overdue AR (60+) uses the same ageing brackets as the AR Ageing report so the two figures always match.
6. Stock Value is at cost using the company's costing method (FIFO/AVCO per system settings).
7. The branch comparison chart renders only when the user can see two or more branches.
8. Currency displays in base currency; foreign-currency documents are converted at their recorded rates.

## Edge Cases & Error Handling

- **First month of trading / no prior-year data**: trend chart renders the single available series and suppresses the comparison legend instead of plotting an empty line.
- **Slow query on a large ledger** (real-time AR across years): tiles load independently with per-tile skeletons; one slow tile never blocks the page. If a tile times out it shows a retry state.
- **Month-end backdating** (invoice posted today, dated last month): MTD reflects document date, so "Today's Sales" and "MTD" can legitimately diverge; tile tooltips explain the basis.
- **Negative day** (credit notes exceed invoices): tiles display negative values in red rather than clamping to zero.
- **Branch with no workshop**: "Open Job Cards" tile hides for that branch scope rather than showing a permanent 0.
- **Timezone edges**: "today" is the company-local calendar day, not UTC, so late-evening sales don't leak into tomorrow.

## Key Tables

Read-only consumer — owns no tables. Reads: `invoices`/invoice lines (Sales), `customer_ledger`/AR balances (Finance), `stock_levels` + costing (Inventory), `job_cards` (Workshop), sales budgets (targets).
