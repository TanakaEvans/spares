# 9.3 Inventory Reports

> Stock health, ageing, movement, and value — the buyer's and stock controller's toolkit. Part of [Module 9: Reports & Analytics](../09-reports-analytics.md).

## Purpose

Inventory is where a spares business's cash lives. These reports expose whether that cash is working: what is on hand and available, what needs reordering, what has been sitting for a year (dead stock in slow-moving brake drums is money that could be fast-moving oil filters), and whether the book value reconciles to the general ledger.

The suite covers nine reports: Stock on Hand, Reorder Report, Stock Ageing, Dead Stock, ABC Analysis, Stock Movement, Stock Value, Stock Take Variance, and Inter-branch Transfer. The Reorder Report is action-oriented — it creates purchase requisitions directly — while Stock Movement is forensic, giving the full in/out ledger for investigating discrepancies.

## User Roles & Permissions

| Role | Access |
|------|--------|
| Super Admin / Owner | All reports, all branches |
| Branch Manager | Own branch |
| Purchasing Officer (Buyer) | Stock on Hand, Reorder, Ageing, Dead Stock, ABC, Price-relevant views; can create requisitions |
| Warehouse Staff | Stock on Hand, Movement, Transfer, Stock Take Variance (no values if cost-hidden) |
| Accountant | Stock Value, Stock Take Variance (for GL reconciliation) |
| Reports Only | Per role config |

## Workflow

```
[Weekly buying review]
        │
        ▼
[Reorder Report: parts below reorder point]
        │                      ▲
        ▼                      │ reorder levels maintained in Inventory
[Review suggested qtys,        │
 preferred supplier,           │
 last order date]              │
        │
        ▼
[Tick lines → one-click Create Purchase Requisitions]
        │
        ▼
[Requisitions flow into Purchasing module approval]

Parallel monthly cycle:
[Stock Ageing] → [Dead Stock list] → [decide: return to supplier /
                                      mark down / write off]
```

1. **Monitor** — Stock on Hand with flags (below reorder, out of stock, negative) is the daily view.
2. **Reorder** — the Reorder Report computes qty-to-order (reorder level − available, adjusted for on-order); selected lines become purchase requisitions in one click.
3. **Age** — Stock Ageing brackets stock at 0–30, 31–60, 61–90, 91–180, 180+ days with value per bracket; Dead Stock isolates 12-month no-movers with a recommended action.
4. **Classify** — ABC Analysis tags parts A (top 20% by sales value), B (next 30%), C (bottom 50%) to focus buying attention.
5. **Reconcile** — Stock Value by category/branch ties to the Inventory GL account; Stock Take Variance documents count results and sign-off.

| Reorder report (actionable) | `reports.inventory.index?report=reorder` | Grid with selection + "Create Requisitions" |

**Primary screen — Reorder Report**: filterable grid (branch, category, supplier) with columns part, branch, on hand, on order, reorder level, suggested qty to order, preferred supplier, last order date. Checkbox column with select-all-by-supplier; footer button "Create Purchase Requisitions" groups the ticked lines by supplier into draft requisitions and links to them.

## Fields & Validation

Shared filters:

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| branch | select | No | permitted branches only |
| category / brand | select | No | — |
| status | select | No | active/discontinued/all |
| as_at date | date | Ageing/Value reports | not in the future |
| movement date range | date pair | Movement report | to >= from |
| dead-stock window | select | Dead Stock | 6 or 12 months |

Requisition creation from the Reorder Report validates each line: suggested qty > 0, a supplier resolvable (preferred or manually chosen), and the part not already on an open requisition (warned, not blocked).

## Business Rules

1. Available = on hand − reserved; all flags (below reorder, out of stock) test *available*, not raw on hand.
2. Suggested order qty accounts for open purchase orders: reorder level − available − on order, floored at zero and rounded up to the supplier's MOQ/pack size.
3. Stock Ageing dates stock by receipt date of the remaining layers (FIFO layers or receipt history under AVCO); value per bracket is at cost.
4. Dead stock = zero *outward* movement in the window; receipts alone don't reset the clock.
5. ABC classification recomputes from a rolling 12 months of sales value; classification changes are logged so a part's drift from A to C is visible.
6. Stock Value uses the company costing method and must reconcile to the Inventory GL control account; the report footer shows the GL balance and the difference.
7. Stock Take Variance is immutable once the take is signed off; the report always names the counter and approver.
8. Negative stock rows appear only where negative stock is allowed (per-branch setting) and are always red-flagged.
9. Inter-branch Transfer report includes status (pending / in transit / received) — "in transit" value belongs to the sending branch until receipt.

## Edge Cases & Error Handling

- **Part below reorder at branch A, surplus at branch B**: Reorder Report shows other-branch availability inline so the buyer can raise a transfer instead of a PO.
- **Reorder level not set** (new part): excluded from the Reorder Report but counted in a "parts without reorder levels" data-quality note at the top.
- **Ageing under AVCO with mixed-age stock**: brackets are approximated from receipt history; the report states the method so auditors aren't misled.
- **Requisition creation for a supplier with no price on file**: line carries last cost with a "price unconfirmed" flag into the requisition.
- **Stock Value vs GL mismatch**: the report surfaces the delta and links to the Movement report filtered to unposted/orphan transactions — the primary reconciliation tool.
- **Transfer dispatched but never received** (report run mid-transfer): shows under "in transit" with days-in-transit; > X days highlights for follow-up.
- **Export of full stock file for buying review**: Excel export includes flags as filterable columns, matching on-screen data exactly.
