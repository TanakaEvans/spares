# 9.4 Financial Reports

> The statutory and management accounting report set, surfaced through the reports hub. Part of [Module 9: Reports & Analytics](../09-reports-analytics.md).

## Purpose

Financial reports present the accounting truth of the business: Trial Balance, Income Statement (Revenue − COGS = Gross Profit − Expenses = Net Profit), Balance Sheet, Cash Flow, AR/AP Ageing, VAT Summary, and Bank Reconciliation. The detailed accounting logic lives in [Module 7: Finance & Accounts](../07-finance-accounts.md); this sub-module is the reporting surface — consistent filters, export, scheduling, and access control alongside the rest of the reports hub.

For a spares business the recurring uses are concrete: the monthly P&L for the owner (a default scheduled report on the 3rd), the VAT Summary for the tax return each period, AR Ageing to drive collections, and AP Ageing to plan supplier payments around cash flow.

These are the most sensitive reports in the system and carry the tightest role gating.

## User Roles & Permissions

| Role | Access |
|------|--------|
| Super Admin / Owner | All financial reports, all branches |
| Accountant | All financial reports |
| Accounts Clerk | AR Ageing, AP Ageing, VAT Summary; no P&L/Balance Sheet |
| Branch Manager | View-only P&L for own branch (profit centre), AR Ageing for own branch |
| Sales Manager | AR Ageing only (collections context) |
| All other roles | No access |

## Workflow

```
[Month-end close in Module 7]
            │
            ▼
[Open Financial Reports hub] → [Pick report + period]
            │
            ▼
[Run: figures pulled from GL / subledgers]
            │
      ┌─────┼───────────────┐
      ▼     ▼               ▼
[Review  [Export PDF     [Schedule monthly
 on      for board /      delivery (9.8):
 screen]  accountant]     P&L 3rd, ageing 1st]
```

1. **Close first** — figures are only final after the Finance module's period-close routine; reports run mid-period are labelled provisional.
2. **Select period** — month/quarter/year or custom range; comparatives (prior period, prior year, budget) toggle on.
3. **Run** — statements are built from GL balances; ageing reports from open subledger items; VAT Summary from output vs input VAT per period.
4. **Distribute** — export to PDF/Excel or schedule (Monthly P&L to owner and accounts on the 3rd; AR/AP Ageing on the 1st).

## Screens

| Screen | Route | Purpose |
|--------|-------|---------|
| Financial reports hub | `reports.finance.index` | Report list + period selector (`Reports/Finance/Index.jsx`) |
| Statement view | `reports.finance.index?report=income-statement` etc. | Rendered statement with comparatives |
| Ageing views | `reports.finance.index?report=ar-ageing` / `ap-ageing` | Bucketed ageing grids |

**Primary screen — Statement view (Income Statement)**: period selector and comparative toggles at top; statement body grouped Revenue → COGS → Gross Profit → Expenses → Net Profit, each line expandable to its GL accounts and from there to journal drill-down. A "provisional" watermark shows for unclosed periods. Multi-branch users get a profit-centre column toggle.

## Fields & Validation

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| period / date range | select or date pair | Yes | must fall within existing financial years; to >= from |
| comparative | select | No | none / prior period / prior year / budget |
| branch / profit centre | select | No | permitted scope only |
| ageing as-at date | date | Ageing reports | not in the future |
| ageing basis | select | No | invoice date or due date (default due date) |

## Business Rules

1. Trial Balance must balance — a debit/credit imbalance renders a prominent error banner (data corruption signal) instead of a quietly wrong report.
2. Statements read from posted journals only; drafts and unposted documents never appear.
3. AR/AP Ageing buckets (current / 30 / 60 / 90+) match the dashboard and customer/supplier reports exactly — one bucketing definition system-wide.
4. VAT Summary separates output VAT (sales) and input VAT (purchases) per tax period and reconciles to the VAT control accounts; the report is the source for the statutory return.
5. Bank Reconciliation reports cleared vs outstanding items per bank account, using the matching tolerance from system settings (`bank_rec_tolerance`).
6. Closed periods are immutable — re-running a closed period always reproduces the same figures; late adjustments post into the current open period.
7. Branch P&L uses GL profit centres (`gl_profit_centre_id` on branches, see [10.3](../10-system-administration/10.3-branch-management.md)); unallocated central costs show in a "Head Office" column, not silently spread.
8. Access is per-report, not module-wide — an accounts clerk sees ageing but not the P&L.

## Edge Cases & Error Handling

- **Report run mid-period**: rendered with a "provisional — period not closed" watermark on screen and on exports.
- **Financial year change** (e.g. moving year-start per company setup): historical years keep their original boundaries; comparatives across the change are flagged as non-comparable.
- **Foreign-currency creditor on AP Ageing**: shown at the rate on the as-at date with the FX variance memo column; totals in base currency.
- **Payment on account not yet allocated to invoices**: AR Ageing shows it as an unallocated credit in "current", so the customer total is right even before allocation.
- **VAT rate change mid-period**: VAT Summary splits lines by rate; a single blended rate is never assumed.
- **Bank rec with items older than the period**: outstanding items carry forward and remain listed until cleared, however old.
