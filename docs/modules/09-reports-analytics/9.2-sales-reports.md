# 9.2 Sales Reports

> Sales performance sliced by period, part, category, customer, and salesperson. Part of [Module 9: Reports & Analytics](../09-reports-analytics.md).

## Purpose

Sales reports answer the daily operational questions — what did we sell today, through which cashiers, paid how — and the strategic ones: which parts and categories carry the margin, which customers matter, how well quotes convert, and what returns are costing. They are the primary evidence base for pricing, staffing, and buying decisions.

The suite covers nine reports: Daily Sales Summary, Sales by Period, Sales by Part, Sales by Category, Sales by Customer, Sales by Salesperson/Cashier, Quotation Conversion, Back-order Report, and Returns Analysis. All share a common filter bar (date range, branch, and dimension-specific filters) and Excel/PDF export.

Margin visibility is the sensitive part: cost and margin columns reveal the business's markups, so they are permission-gated separately from the revenue figures.

## User Roles & Permissions

| Role | Access |
|------|--------|
| Super Admin / Owner | All reports, all branches, margin visible |
| Branch Manager | Own branch, margin visible |
| Sales Manager | All sales reports, margin visible |
| Cashier / Counter Staff | Own shift's Daily Sales Summary only, no margin |
| Accountant | All reports, margin visible |
| Reports Only | Assigned reports/branches per role config |

## Workflow

```
[Open Sales Reports hub] → [Pick report] → [Set filters:
        date range, branch, salesperson, customer, category]
                              │
                              ▼
                  [Run → results table + summary row]
                              │
               ┌──────────────┼───────────────┐
               ▼              ▼               ▼
        [Drill-down     [Export Excel   [Schedule it
         (period→day→    / PDF]          (see 9.8)]
         invoice)]
```

1. **Select report** from the hub page; each report opens with sensible defaults (Daily Summary defaults to today, Sales by Period to MTD).
2. **Filter** by branch, salesperson, customer, customer group, category as applicable.
3. **Run** — datasets under 10,000 rows filter/sort client-side; larger sets paginate server-side.
4. **Drill** — period rows expand to days, days to invoices, invoices open the source document.
5. **Export or schedule** — Excel via laravel-excel, PDF via dompdf, or hand the configured report to [Scheduled Reports](9.8-scheduled-reports.md).

**Primary screen — Sales reports hub**: left sidebar lists the nine reports; the main pane holds the filter bar, a summary strip (total revenue excl VAT, VAT, incl VAT, cost, gross margin, margin % — cost/margin only for permitted roles), and the results grid. The Daily Sales Summary view adds panels for payment-method split (cash/card/account), transaction count, average transaction value, top 5 parts, cashier breakdown, and VAT collected.

## Fields & Validation

Shared filter bar:

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| date_from / date_to | date | Yes | to >= from; range capped (e.g. 366 days) for row-level reports |
| branch | select | No | limited to permitted branches |
| salesperson | select | No | active users with sales roles |
| customer / customer group | select | No | — |
| category | select | No | drill-down to subcategory in Sales by Category |
| granularity | select | Per report | daily/weekly/monthly/quarterly/yearly (Sales by Period) |

## Business Rules

1. Revenue is recognised on invoice date; credit notes post as negatives in the same period, so period totals are net of returns.
2. Margin = revenue excl VAT − cost of sales at the costing method in force when the line was sold; recalculating history with today's costs is never done.
3. Cost and margin columns render only for roles with the margin permission; exports honour the same rule (no margin columns in a cashier's export).
4. Quotation Conversion counts a quote as converted when any of its lines reach an order/invoice before expiry; win rate = converted ÷ issued per salesperson, and lost quotes require a reason code to appear in lost-quote analysis.
5. Back-order Report sorts oldest-first and joins supplier ETA from open POs; lines with no linked PO show "not yet ordered" as an explicit state.
6. Returns Analysis groups credit notes by reason code, salesperson, and part; return rate % = credited qty ÷ sold qty per category over the same period.
7. Sales by Part includes on-hand stock, last sale date, and sell-through rate so it doubles as a buying-review sheet.
8. All reports enforce branch-level access control server-side.

## Edge Cases & Error Handling

- **Invoice and its credit note straddle periods** (sold March, returned April): each hits its own period — March is not restated; Returns Analysis makes the April impact visible.
- **Salesperson deactivated mid-period**: still appears in historical rows (name suffixed "(inactive)"); absent from the filter's default list but selectable via "include inactive".
- **Zero-sales day**: Daily Summary renders with zeros and an explicit "no transactions" note rather than an error — needed for scheduled email delivery.
- **Part sold under a superseded number**: Sales by Part groups by the part record actually invoiced; a toggle "roll up supersession chains" merges chain history for buying decisions.
- **Mixed-payment invoice** (part cash, part card): payment-method split allocates by tender amounts, so method totals reconcile to takings, not invoice counts.
- **Huge exports** (year of invoice lines): export runs as a queued job with an emailed download link instead of a blocking request.
