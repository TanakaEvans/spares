# 7.7 Financial Reporting

> Trial balance, P&L, balance sheet, and the operational finance reports — all read from posted journals. Part of [Module 7: Finance & Accounts](../07-finance-accounts.md).

## Purpose

Reporting is where the double-entry discipline pays off. Because every module posts balanced journals to a typed COA, the financial statements are deterministic queries: the **trial balance** lists every account's balance at a date (and proves ΣDR = ΣCR); the **income statement** groups revenue, COGS, and expense accounts over a period into gross and net profit; the **balance sheet** presents assets, liabilities, and equity at a date, balancing because the ledger balances. There is no report-side arithmetic to "fix" — a wrong report means a wrong posting, and drill-down finds it.

For a spares business the operating reports matter as much as the statements. **Gross margin by category** (parts vs oils vs workshop labour) exposes where margin is made and where price lists need work; **AR/AP ageing** run the collections and payment cycles; **sales vs budget** keeps branch managers honest; the **VAT summary** and **bank reconciliation** reports support compliance. All reports share the same conventions: date/period selection, branch filter, drill-down from any figure to journal lines to source documents, and export to Excel/PDF with a print layout.

Reports are also the trust interface with outsiders — the accountant preparing annual statements, the bank reviewing an overdraft, the auditor. Reproducibility is therefore a requirement: the same report with the same parameters over closed periods must return identical figures forever.

## Workflow

Main process: running a report and investigating a figure.

```
Select report (e.g. Income Statement)
        │
Parameters: period/date range, branch (or consolidated),
comparison column (prior period / prior year / budget)
        │
Generate ──> report over posted journal lines only
        │
Figure looks wrong (e.g. COGS % jumped)
        │
Drill level 1: account group → accounts (5100 Cost of Parts…)
Drill level 2: account → journal lines for the period
Drill level 3: journal line → source document
              (invoice, GRN, stock adjustment)
        │
Root cause found (e.g. a write-off posted to COGS)
        │
Export: Excel (data) / PDF (formatted) / print layout
```

1. **Parameterise.** Date-at reports (TB, balance sheet) take an as-at date; period reports (P&L, VAT summary, margin) take a range; all take the branch filter (parent-standard features).
2. **Generate.** Reports read posted journals exclusively — drafts and reversed pairs net out by construction. Closed-period reports may be served from snapshots for speed but must equal the live computation.
3. **Drill.** Every figure decomposes: group → account → journal lines → source document. This chain is the audit answer to "prove this number".
4. **Compare.** P&L and sales reports support side-by-side prior-period, prior-year, and budget columns with variance % — the management-pack format.
5. **Export.** Excel keeps raw rows for the accountant's workpapers; PDF renders the print layout for the pack.

## Fields & Validation

Report parameter form (shared conventions):

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| As-at date | date | Date reports | Any date ≤ today; future blocked |
| Period range | period/date pair | Period reports | start ≤ end; may span periods and years (spanning a year break flags retained-earnings treatment) |
| Branch | select | Yes | Own-branch enforced for branch-scoped roles; "consolidated" for finance roles |
| Comparison | select | No | `prior_period`, `prior_year`, `budget`; budget requires a budget dataset for the range |
| Include zero-balance accounts | boolean | No | Default off |
| Budget upsert (maintenance) | grid/import | FM only | Amount per account per period; import validates account codes exist and are P&L-type |
| Export format | select | On export | `xlsx`, `pdf`; print layout uses the company letterhead settings |

## Business Rules

1. Reports read **posted** journal lines only; draft journals and posting-failure queues ([7.2](7.2-general-ledger.md)) never appear — which is why the close checklist demands those queues are empty.
2. The trial balance must always balance; a non-zero difference is displayed as a system error banner (data-integrity incident), never absorbed into a plug line.
3. Balance sheet retained earnings = prior years' accumulated results + current-year P&L to date, computed — not posted — until year-end closing entries roll it up ([7.8](7.8-period-management.md)).
4. Reports over closed/locked periods are immutable in result: identical parameters return identical figures; snapshots taken at close are validated against live recomputation.
5. Branch consolidation sums branch dimensions and must equal the undimensioned company total — a variance indicates journals missing branch tags, listed for repair.
6. Ageing reports (AR/AP) bucket by due date and must tie to the respective control-account balances ([7.3](7.3-accounts-receivable.md), [7.4](7.4-accounts-payable.md)); the tie-out line prints on the report.
7. Gross margin by category maps revenue and COGS accounts to part categories via the posting mappings ([7.1](7.1-chart-of-accounts.md)); unmapped postings appear in an explicit "Unmapped" row rather than distorting a category.
8. The cash flow statement is derived (indirect method) from P&L and balance-sheet movements; a direct-method view is available from bank/cash journal classifications.
9. Budgets are versioned; reports name the budget version used, and reforecasts never overwrite the original budget.

## Edge Cases & Error Handling

- **P&L run mid-month while unposted sales sit in the posting-failure queue:** the report shows a warning ribbon "N documents pending posting for this range" so nobody presents an understated month.
- **Comparison to prior year when the COA changed:** deactivated accounts still report under their historical group; new accounts show blank comparatives — no forced remapping of history.
- **Branch report totals differ from consolidated:** rule 5's variance list pinpoints untagged journals (usually manual ones); the fix is a re-tagging journal, and the report footnotes the temporary difference until fixed.
- **Report spans the financial year break:** the P&L warns that the range crosses years and offers per-year sub-totals; balance-sheet-as-at within year 2 is unaffected.
- **Excel export of 200k journal lines:** exports above a row threshold run as background jobs with notification, rather than timing out the request.
- **Budget imported against a renamed account code:** import validation rejects unknown codes row-by-row with line numbers; nothing partial loads without a summary of rejects.
- **Auditor requests the pack as at last year-end, today:** locked-period reproducibility (rule 4) guarantees the regenerated statements equal those issued then; the generated-at timestamp distinguishes the print, not the figures.
- **Rounding: statements shown in whole currency units:** rounding is presentation-only; underlying cents are preserved, and rounding differences within a statement resolve on the largest line per standard practice, disclosed in the footer.
