# 3.3 Goods Received Notes (GRN)

> Records the physical arrival, inspection, and putaway of supplier deliveries, updating stock and enabling invoice matching. Part of [Module 3: Purchasing & Procurement](../03-purchasing-procurement.md).

## Purpose

The GRN is where paper meets pallets. When the courier from the local Bosch distributor offloads twelve cartons against PO-20260915-0042, the warehouse must confirm what actually arrived: count every line, inspect for transit damage (a cracked alternator housing, oil filters with dented cans), capture batch numbers on brake fluid and coolant, and put each item away into a bin location so pickers can find it.

Posting the GRN is the single event that increases stock on hand — nothing else in purchasing touches inventory. It writes a `PURCHASE_RECEIPT` entry to the stock ledger at PO cost (plus allocated landed costs for imports) and updates `qty_received` on each PO line. It is also the quantity anchor of 3-way matching: the supplier can only invoice what the GRN says arrived.

Blind receiving is supported for discipline: the receiving clerk counts without seeing ordered quantities, so discrepancies are found by counting, not by copying the PO. Rejected items never enter sellable stock; they sit in a quarantine state pending a return to supplier (3.6).

## User Roles & Permissions

| Role | Access |
|------|--------|
| Receiving Clerk | Create GRN, count, flag rejections, assign bins, save draft |
| Warehouse Supervisor | Post GRNs; approve over-receipts > 10%; enable/disable blind mode |
| Buyer | Read-only; sees receipt progress against own POs |
| Finance (AP) | Read-only; GRN values during invoice matching |
| Quality Inspector (optional role) | Record `qty_rejected` and rejection reasons |

## Workflow

```
Delivery arrives
      │
      ▼
Select open PO(s) for supplier ──► Print receiving sheet / open GRN screen
      │
      ▼
Count & inspect each line ──► enter qty_received
      │
      ├── damaged / wrong item ──► qty_rejected + reason
      │
      ▼
Capture batch / serial / expiry (where flagged on the part)
      │
      ▼
Assign bin locations (putaway suggestions from default bins)
      │
      ▼
[import shipment?] ──► allocate landed costs (freight / duty / clearing)
      │
      ▼
POST GRN ──► stock ledger PURCHASE_RECEIPT ──► PO lines updated
      │                                          │
      ▼                                          ▼
Print bin/barcode labels                 Invoice matching enabled (3.4)
```

1. **Open** — Clerk selects the supplier and one or more open POs (a supplier often combines several POs in one truck); a draft GRN is created with the delivery note number, carrier, and tracking reference.
2. **Count** — Each line's actual quantity is entered (in blind mode the ordered quantity is hidden until the count is saved).
3. **Inspect** — Damaged or incorrect items are recorded as `qty_rejected` with a reason; accepted = received − rejected.
4. **Putaway** — Each accepted line gets a bin location; the part's default bin is suggested, overflow bins offered when full.
5. **Landed costs** — For import receipts, freight/insurance/duty/clearing amounts are entered and allocated by value, weight, or equally.
6. **Post** — Supervisor (or clerk, within tolerance) posts; stock, PO lines, and average cost update atomically; the GRN becomes read-only.

## Screens

| Screen | Route | Purpose |
|--------|-------|---------|
| Receive GRN | `purchasing.grns.create` | Select PO(s), count, inspect, putaway, post |
| GRN list | `purchasing.grns.index` | History and drafts, filter by supplier/status/date |
| GRN detail | `purchasing.grns.show` | Read-only posted GRN with ledger entries and labels reprint |

**Primary screen — Receive GRN.** Header: supplier, selected PO numbers, received date, carrier, tracking number, supplier delivery note number. Main area: line grid grouped by PO — part, supplier part number, qty ordered (hidden in blind mode), qty received, qty rejected + reason, bin location selector, batch/expiry inputs appearing only for batch-tracked parts. A discrepancy column highlights over/under lines in amber/red. Side panel: landed-cost entry (import GRNs). Footer actions: *Save draft*, *Post GRN* (with over-receipt approval prompt when triggered), *Print labels*.

## Fields & Validation

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| po_id(s) | multi-select | Yes | Open/partial POs of the chosen supplier only |
| received_date | date | Yes | Not future-dated; not before PO order date |
| delivery_note_number | text | Yes | Max 100; warned if duplicate for this supplier |
| carrier / tracking_number | text | No | Max 100 each |
| line: qty_received | decimal | Yes | ≥ 0; over-receipt > 110% of outstanding requires supervisor approval |
| line: qty_rejected | decimal | Conditional | ≤ qty_received; reason required when > 0 |
| line: bin_location_id | select | Yes (accepted > 0) | Active bin at receiving branch |
| line: batch_number | text | Conditional | Required when part is batch-tracked |
| line: expiry_date | date | Conditional | Required for perishables (brake fluid, adhesives); must be future |
| landed cost: amount | decimal | Conditional | > 0; allocation method required per cost row |

## Business Rules

1. Posting is irreversible; corrections go through a supplier return (3.6) or a stock adjustment — never by editing a posted GRN.
2. Rejected quantities never enter sellable stock; they are held in a quarantine bin and pre-populate a draft supplier return.
3. Over-receiving beyond 10% of a line's outstanding quantity requires supervisor approval, recorded with approver and timestamp on the GRN.
4. Landed costs are folded into the effective unit cost of each received line (per the allocation method) and therefore into stock valuation — the supplier's invoice for freight is matched separately against the landed-cost record, not the goods PO.
5. A part flagged batch- or serial-tracked cannot be posted without its identifiers; the post button is disabled with per-line messages.
6. Zero-received lines are permitted (short delivery): the PO line stays open and the GRN records the shortfall for the supplier scorecard.
7. In blind mode, a variance beyond tolerance forces a recount confirmation before the discrepancy is accepted.

## Edge Cases & Error Handling

- **Supplier delivers more than ordered** (e.g. NGK plugs come in trade packs of 10, ordered 25, received 30): within 10% posts normally as over-receipt; beyond it, supervisor approval or the excess is rejected and routed to return/keep-and-amend decision.
- **GRN posted twice for the same delivery note**: the duplicate delivery-note warning fires at header save; if forced through, the second GRN can only receive against *remaining* outstanding PO quantity, so a true duplicate finds nothing to receive.
- **Delivery contains a part not on any selected PO**: it cannot be added to the GRN; the clerk logs it as an "unordered item" note and the buyer decides — new PO + supplemental GRN, or refuse and send back with the driver.
- **Wrong part in the right box** (supplier picked Bosch 0 986 452 041 instead of 0 986 452 044): received qty 0 on the ordered line, unordered-item note for the wrong stock; PO line remains open.
- **Bin full during putaway**: overflow bin suggestions shown; the clerk may split one line across multiple bins (multiple bin rows per grn_line).
- **Network failure mid-post**: posting is a single DB transaction; a failed post leaves the GRN in `draft` with nothing written to the ledger, and a retry is safe.
- **Landed cost invoice arrives weeks after the goods**: a posted import GRN accepts *late* landed-cost allocation via a cost-adjustment entry that revalues remaining on-hand quantity only (sold units flow to COGS variance).
- **Expiry date earlier than an existing batch on hand**: allowed, but the system warns and FEFO picking will consume the new batch first.

## Key Tables

- `goods_received_notes` — GRN header: PO/supplier/branch, status, carrier and delivery references, posting timestamp.
- `grn_lines` — per part: qty ordered/received/accepted/rejected, cost, bin, batch/expiry.
- `landed_costs` — freight/insurance/duty/clearing amounts with allocation method per GRN.
