# 3.8 Price Comparison

> A buyer's tool showing the same part across suppliers — last costs, lead times, MOQs — to pick the best source. Part of [Module 3: Purchasing & Procurement](../03-purchasing-procurement.md).

## Purpose

Most fast-moving spares are multi-sourced. An oil filter for the Toyota Hilux 2.8 GD-6 might be available as genuine Toyota from the franchise distributor, as a Bosch equivalent from the local Bosch agent, as Fram from a wholesaler, and as an unbranded OEM-spec unit from an import consolidator — at four different prices, four different lead times, and four different minimum order quantities. The buyer converting this morning's requisitions needs those options side by side, not from memory.

Price Comparison assembles, per part, every approved supplier with: last purchase cost (and date, so a six-month-old price is visibly stale), the supplier's current list/quoted price where a price list is loaded, standard lead time, MOQ, and soft factors from supplier performance — fill rate, on-time percentage, and credits ratio. Cheapest is not always best: a supplier 4% cheaper who delivers at 60% fill rate costs more in lost workshop hours than the price saves, and the screen is designed to make that trade-off visible.

It is deliberately a *decision-support* tool, not a document: it creates nothing itself, but launches PO creation with the chosen supplier pre-selected, and is embedded as a side panel inside requisition conversion (3.1).

## User Roles & Permissions

| Role | Access |
|------|--------|
| Buyer | Full use; launch PO from comparison; request quotes |
| Procurement Manager | Full use; maintain supplier price lists; set preferred-supplier flags |
| Branch Manager | Read-only |
| Counter Sales | No access (sees only sell prices in Sales module) |

## Workflow

```
Entry points:
  Part enquiry │ Requisition conversion (3.1) │ Reorder review
        │
        ▼
Select part (or part list)
        │
        ▼
System assembles per approved supplier:
  last cost + date · list price · lead time · MOQ · fill rate · on-time %
        │
        ▼
Buyer compares ── optionally: Request quote (RFQ email, logged)
        │
        ▼
Choose supplier ──► Create PO (3.2) pre-filled
        │
        ▼
(choice + reason logged when not the cheapest source)
```

1. **Select** — The buyer searches a part, or arrives with a part pre-loaded from a requisition line or reorder alert.
2. **Compare** — The grid shows one row per approved supplier with cost, currency-normalised landed estimate for import sources, and performance columns; the preferred supplier row is highlighted.
3. **Quote** — For stale prices, a Request-for-Quote email can be sent to selected suppliers; replies are keyed in as quoted prices with validity dates.
4. **Act** — "Create PO" hands off to 3.2 with supplier and cost pre-filled; when invoked from requisition conversion, the choice writes back to the PR line's supplier.

## Screens

| Screen | Route | Purpose |
|--------|-------|---------|
| Price comparison | `purchasing.price-compare` | Per-part supplier comparison grid |
| Comparison side panel | (embedded in `purchasing.requisitions.show`) | Same grid scoped to the PR line's part |

**Primary screen — Price comparison.** Header: part search with the selected part's details (internal SKU, description, OE cross-references, current stock and average monthly usage). Main area: supplier grid — supplier name (preferred badge), supplier part number, last cost + purchase date (aged prices tinted amber > 90 days, red > 180), current list/quoted price + validity, effective landed estimate (imports), lead time in days, MOQ, fill rate %, on-time %, credits ratio. Row actions: *Create PO*, *Request quote*, *View purchase history*. Footer: comparison basis toggle (last cost / list price / landed estimate) and a price-history sparkline for the selected supplier.

## Fields & Validation

The screen is read-mostly; keyed data is limited to quote capture:

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| part_id | part search | Yes | Active part |
| quote: supplier_id | select | Yes | Approved supplier for the part (or add-approval prompt) |
| quote: quoted_price | decimal | Yes | > 0; currency per supplier default |
| quote: valid_until | date | Yes | Future date; expired quotes drop out of the grid |
| quote: moq / lead_time_days | decimal / int | No | ≥ 0; overrides supplier defaults for this part |
| preferred flag | toggle | — | Procurement Manager only; one preferred supplier per part |

## Business Rules

1. Only suppliers on the part's approved supplier list appear; adding a new source is a supplier-part approval action (Procurement Manager), not a free-text row.
2. Import supplier rows display a *landed estimate*: FOB price plus the part's historical average landed-cost uplift percentage, so sea-freight sources compare honestly against local ones.
3. Last cost comes from the most recent posted GRN line (actual received cost including landed allocation), not from the PO — the price that really happened.
4. Quoted prices expire at `valid_until` and are excluded thereafter; the RFQ log keeps them for negotiation history.
5. Choosing a supplier other than the cheapest (on the active comparison basis) prompts for a reason code (`lead_time`, `quality`, `moq`, `stock_rotation_deal`, `other`) — logged, not blocked.
6. Performance columns (fill rate, on-time %, credits ratio) are computed over a rolling 12 months from GRN vs PO data and credit-note history.
7. Currency conversion for display uses the current daily rate and is labelled as indicative; the PO will lock its own rate (rule 3.2).

## Edge Cases & Error Handling

- **Part has only one approved supplier**: the grid renders with a "single-sourced" banner and a one-click "find alternatives" that searches other suppliers by OE cross-reference — surfacing that the Bosch agent also lists this filter under its cross number.
- **No purchase history at all (new part)**: rows show list/quoted prices only; the last-cost column reads "never purchased" rather than zero, and landed estimates fall back to the category-average uplift.
- **Supplier price list loaded with an obviously wrong price** (decimal slip: 4.20 vs 420.00): prices deviating > 5× from last cost render with a data-error flag and are excluded from "cheapest" ranking until confirmed.
- **Two suppliers quote different pack sizes** (plugs per-unit vs per-box-of-10): comparison normalises to the part's stocking UOM using the supplier-part pack-size factor; rows missing a factor show "pack size unverified".
- **Requisition line's suggested supplier fails approval mid-flow** (removed from approved list): the embedded panel greys that row and requires reselection before conversion proceeds (matches 3.1 edge case).
- **Stale everything** (no price newer than 12 months on a slow mover): the grid header prompts an RFQ blast to all approved suppliers in one action.
- **Quote received in a currency the system has no rate for**: capture blocked until the currency/rate is set up in Finance; the quote parks as draft.
