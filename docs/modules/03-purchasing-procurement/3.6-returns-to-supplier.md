# 3.6 Returns to Supplier

> Manages sending damaged, incorrect, or excess stock back to suppliers under an RMA, through to receiving the credit. Part of [Module 3: Purchasing & Procurement](../03-purchasing-procurement.md).

## Purpose

Stock goes back to suppliers for four distinct reasons, and each has different rules: **damaged** goods found at receiving (the cracked alternator from the GRN inspection), **incorrect parts** (the Bosch distributor picked the wrong filter code), **excess stock** negotiated back under a stock-rotation agreement (slow-moving Hilux 2.4 GD glow plugs the branch over-ordered), and **warranty** returns of failed parts being sent back as physical evidence for a claim.

Without a controlled process, returned stock is where inventory quietly disappears: parts leave the building with a driver, no paperwork follows, and three months later the supplier statement shows no credit. This sub-module forces the discipline: a return document is raised, the supplier's Return Merchandise Authorisation (RMA) number is obtained *before* anything ships, the shipment posts a `RETURN_OUT` stock ledger entry, and the return stays open on a chase list until the supplier's credit note (3.5) closes it.

Returns can only reference parts actually received from that supplier, which stops the perennial abuse of returning grey-import stock to the official distributor.

## User Roles & Permissions

| Role | Access |
|------|--------|
| Warehouse Clerk | Create draft returns (auto-drafted from GRN rejections), pick and pack |
| Buyer | Request RMA from supplier, capture `supplier_rma`, approve return |
| Warehouse Supervisor | Post shipment (stock deduction), print return documentation |
| AP Clerk | Link incoming credit note; view open-returns chase list |
| Procurement Manager | Approve excess-stock returns (commercial negotiation), cancel returns |

## Workflow

```
Trigger:
  GRN rejection │ wrong part found later │ stock-rotation deal │ warranty claim
        │
        ▼
Create Return Request (draft) ──► Buyer approval
        │
        ▼
Request RMA from supplier ──► capture supplier_rma  ◄── (blocked from shipping without it)
        │
        ▼
Pick & pack return items ──► Post shipment
        │                        │
        │                        ▼
        │              Stock ledger: RETURN_OUT
        ▼
Status: shipped ──► chase list ──► Supplier credit note captured (3.5)
                                        │
                                        ▼
                              Status: credit_received (closed)
```

1. **Create** — A draft return is raised, most often pre-populated from GRN rejected lines; each line carries quantity, unit cost (from the original GRN), condition, and reason notes.
2. **Approve** — The buyer confirms the return is justified and commercially agreed; excess-stock returns need Procurement Manager approval since restocking fees may apply.
3. **RMA** — The buyer requests authorisation; the supplier's RMA reference is mandatory before the return can move to shipping.
4. **Ship** — Warehouse picks the items (from quarantine or normal bins), packs with the return document, and posts the shipment — this writes the `RETURN_OUT` stock entry and sets a collection/ship date.
5. **Credit** — When the credit note arrives it is captured in 3.5 and linked, closing the return; the chase list ages any return shipped > 30 days without credit.

| Screen | Route | Purpose |

| Returns list | `purchasing.returns.index` | Open returns, chase list (shipped-no-credit), history |
| Create return | `purchasing.returns.create` | Lines from GRN/stock, reason, condition |
| Return detail | `purchasing.returns.show` | RMA capture, ship posting, linked credit note |

**Primary screen — Return detail.** Header: return number, supplier, original GRN link, reason category, status chip, RMA number field (highlighted red while empty), collection date. Main area: line grid — part, qty returned, unit cost, condition (`new`/`damaged`/`used`), reason notes, source GRN line. Side panel: document timeline (created → approved → RMA → shipped → credited) with dates and users. Footer actions by status: *Approve*, *Capture RMA*, *Post shipment*, *Link credit note*, *Cancel*.

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| supplier_id | select | Yes | Active supplier |
| original_grn_id | lookup | Yes for damaged/incorrect | Posted GRN of this supplier |
| reason | select | Yes | `damaged` / `incorrect_part` / `excess_stock` / `warranty` |

| collection_date | date | No | ≥ today when scheduling collection |
| line: part_id | lookup | Yes | Must have purchase history from this supplier |

| line: unit_cost | decimal | Auto | Cost from source GRN line; editable only by Procurement Manager |
| line: condition | select | Yes | `new` / `damaged` / `used` |
| line: reason_notes | text | Conditional | Required when condition = `damaged` |

## Business Rules

1. Posting the shipment writes a `RETURN_OUT` stock ledger entry at the line's unit cost; quarantined (GRN-rejected) items deduct from quarantine, sellable excess stock deducts from its bin.
2. A return may only contain parts with receipt history from the named supplier; the quantity cap is cumulative (received − previously returned).
3. `supplier_rma` is mandatory before status `shipped` — no authorisation, no truck.
4. Expected credit value = Σ(qty × unit_cost); the linked credit note is validated against it in 3.5, with shortfalls kept on the short-credited chase list.
5. Excess-stock returns may carry a restocking-fee percentage; the fee reduces the expected credit and is disclosed on the approval dialog.
6. Warranty-reason returns must link a warranty claim (4.7); the physical return and the financial claim are tracked separately but cross-referenced.
7. Cancelling a return after items were moved to a returns staging bin generates a putaway task to bring them back to sellable stock (or back to quarantine if damaged).

## Edge Cases & Error Handling

- **Supplier refuses the RMA** (out of return window): the return is closed as `rejected-by-supplier`; damaged items are written off via stock adjustment with the refusal recorded — the write-off report separates these from shrinkage.
- **Driver collects fewer boxes than picked** (one carton missed): the shipment post supports a partial-ship split — shipped lines post `RETURN_OUT`, the remainder stays `approved` for the next collection.
- **Credit arrives before the goods ship** (supplier credits on photos of transit damage): the credit note links to the return at `approved` status; shipping may then be waived by the Procurement Manager, converting the return to a disposal instruction.
- **Part was received from two suppliers** (dual-sourced oil filter): the quantity cap is evaluated per supplier from batch/GRN traceability; the return line requires selecting the source GRN when ambiguous.
- **Return posted, then the same part is needed urgently for a customer**: shipped stock is gone — the screen warns at posting when on-hand after return falls below reserved quantity.
- **RMA number typo**: editable until `shipped`; after that, corrections append a note rather than overwriting (the printed document already left with the goods).
- **Aged open return (> 30 days shipped, no credit)**: appears on the chase list with supplier contact details and one-click "chase email" logging.
