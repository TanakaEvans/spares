# 4.2 Labour Management

> Defines the workshop's standard operations, flat-rate book times, and labour rates by customer type and vehicle make. Part of [Module 4: Workshop Management](../04-workshop-management.md).

## Purpose

Labour is the workshop's product, and this sub-module is its catalogue. Every standard operation the workshop sells — "ENG-OIL-01 Engine oil & filter change", "BRK-PAD-F Front brake pads replace", "SUS-SHK-R2 Rear shocks replace (pair)" — is a labour code with a category, a flat-rate book time, and a default charging method. When a service advisor builds a job card, they pick labour codes rather than inventing free-text lines, which makes quoting instant, billing consistent, and technician efficiency measurable (book hours sold vs clock hours worked).

Three charging methods coexist. **Flat rate** charges the book time regardless of actual duration — the industry standard for known operations, and the mechanism that rewards fast technicians. **Actual time** bills the clock, used for diagnostics and electrical gremlins where no book time can be honest. **Fixed price** honours a pre-agreed quote. Book times can vary by vehicle make and model — a cambelt on a transverse V6 is not the 1.2 hours it is on a Hilux 2.8 GD-6 inline four — via make-specific rate overrides.

Rates are equally structured: a "Standard" retail hourly rate, a discounted "Trade" rate for mechanic account-holders, and negotiated "Fleet" rates, optionally differing per branch.

## User Roles & Permissions

| Role | Access |
|------|--------|
| Workshop Manager | Create/edit labour codes, book times, and rates; deactivate codes |
| Workshop Foreman | View all; propose new codes and time corrections |
| Service Advisor | Select codes on job cards; view rates applicable to the customer |
| Technician | View code descriptions and book times for assigned work |
| Finance | Read-only; rate audit for invoicing checks |

## Workflow

```
New standard operation identified (foreman proposal)
        │
        ▼
Workshop Manager creates labour code
  code · description · category · default rate type · flat-rate hrs
        │
        ├── make-specific times? ──► add labour_code_rates rows
        │                            (make, optional model, hrs)
        ▼
Code active ──► available in job-card labour picker
        │
        ▼
Used on job cards ──► efficiency data accumulates
        │
        ▼
Periodic review: actual-vs-book variance report ──► adjust book time / rates
        │
        ▼
Obsolete operation ──► deactivate (history preserved)
```

1. **Create** — The manager defines the code (unique, mnemonic pattern `CAT-OP-nn`), description, category, default rate type, book hours, and default hourly rate.
2. **Specialise** — Where make matters, per-make (and optionally per-model) book-time overrides are added; the job card resolves the most specific match: model → make → default.
3. **Rate setup** — Named rates ("Standard", "Trade", "Fleet") map to customer types and optionally branches; the job card resolves rate by the customer's type at the job's branch.
4. **Use** — Advisors pick codes on job cards; billable hours default from the resolved book time, editable only within rate-type rules.
5. **Review** — The variance report (average actual vs book per code) drives book-time corrections; deactivation hides a code from pickers without touching history.

**Primary screen — Labour code detail.** Header: code, description, category chip, active toggle, default rate type. Main area: **Book time** panel (default flat-rate hours + the make/model override table with add-row inline editing), **Pricing** panel (default rate per hour, computed example charge), **Usage** panel (times used last 12 months, average actual hours vs book, efficiency variance sparkline — the evidence for adjusting book time). Footer: *Save*, *Duplicate as new code*, *Deactivate*.

## Fields & Validation

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| code | text | Yes | Unique, uppercase, max 20; pattern `AAA-AAA-99` recommended, immutable after first use |
| description | text | Yes | Max 255; shown on customer invoice |
| category | select | Yes | From category list (Engine, Brakes, Suspension, Electrical, Service, Diagnostic...) |
| default_rate_type | select | Yes | `flat_rate` / `actual_time` / `fixed_price` |
| flat_rate_hrs | decimal | Conditional | Required when rate type `flat_rate`; 0.1–99.9 |
| default_rate_per_hr | decimal | Yes | > 0 |
| override: vehicle_make_id | select | Yes (per row) | No duplicate make+model combination per code |
| override: flat_rate_hrs | decimal | Yes (per row) | 0.1–99.9; warn if > 3× default |
| rate: name / rate_per_hr | text / decimal | Yes | Unique name per branch scope; rate > 0 |
| rate: customer_type | select | Yes | One rate per customer type per branch (null branch = all) |

## Business Rules

1. A labour code used on any job card can never be deleted, only deactivated; deactivation removes it from pickers but historic job lines and reports keep the code.
2. Book-time resolution on a job card is most-specific-wins: (make + model) override → make override → code default; the resolved source is stored on the labour line for audit.
3. Rate resolution: the customer's type maps to a named rate at the job's branch; a branch-specific rate beats the global (null-branch) rate; missing mapping falls back to "Standard" with a warning.
4. Changing a code's book time or rate affects only *future* job-card lines; open job cards keep the values captured at line creation (repricing an open line is an explicit advisor action).
5. `actual_time` lines bill from clock records (4.3) — billable hours are read-only until clock-off, then editable downward only (goodwill), never upward past actual.
6. `fixed_price` lines require a quote/estimate reference and ignore hours for billing while still recording actual hours for costing.
7. Warranty labour lines use the supplier claim rate (4.7), not the customer rate, and are excluded from revenue.

## Edge Cases & Error Handling

- **Same operation, wildly different actual times across technicians**: the variance panel splits by technician before anyone "fixes" the book time — a training problem is not a book-time problem.
- **Advisor picks a make-specific code for the wrong vehicle** (model override exists for Hilux, vehicle is a Fortuner): resolution falls to the make-level time silently but the line shows which override level applied; no error, correct behaviour, visible audit.
- **Rate change mid-month while fleet invoicing runs monthly**: job lines carry their captured rate, so a mid-month change never restates existing lines; the fleet statement reconciles line-by-line.
- **Two rates match** (customer type `trade`, both a branch rate and global rate exist): branch wins deterministically; the rates screen shows effective-rate preview per customer type per branch to make this inspectable.
- **Book time set to 0.0 by mistake**: minimum 0.1 validation blocks it — a zero-hour flat-rate line would bill nothing and pollute efficiency stats.
- **Code retired but a template/service package references it**: deactivation warns and lists referencing packages; the package must be updated first.
- **Negotiated one-off discount on labour**: handled by `discount_pct` on the job-card labour line, never by creating a throwaway rate.

## Key Tables

- `labour_codes` — the operation catalogue: code, description, category, rate type, default book time and rate.
- `labour_code_rates` — make/model-specific flat-rate hour overrides.
- `labour_rates` — named hourly rates by customer type and branch.
