# 10.5 System Settings

> The application-wide configuration switchboard — behavioural defaults for every module. Part of [Module 10: System Administration](../10-system-administration.md). **Status: existing, to be extended.**

## Purpose

System Settings centralises the tunable behaviour of SparesPro as key/value settings grouped by category, so business policy changes (a new discount ceiling, a different quote validity) are configuration edits, not code deployments. The parent doc defines the target catalogue across six categories: Inventory (`allow_negative_stock`, `default_cost_method`, `low_stock_alert_days`, `stock_take_freeze_movements`), Sales (`quote_expiry_days`, `max_discount_without_approval`, `allow_credit_over_limit`, loyalty earn/expiry), Purchasing (`po_approval_threshold`, `grn_over_receive_tolerance`, `auto_requisition_on_reorder`), Workshop (`job_card_reminder_mins`, `warranty_labour_rate`, `require_vehicle_on_job`), Finance (`vat_rate_default`, `payment_terms_default_days`, `ar_overdue_hold_days`, `bank_rec_tolerance`), and Notifications (email-on-low-stock/PO-overdue/job-overdue).

Each setting is read by its owning module at decision time — e.g. POS checks `max_discount_without_approval` before demanding a manager PIN; the GRN screen checks `grn_over_receive_tolerance` before accepting an over-delivery. Settings therefore need types, validation, defaults, and an audit trail: a silently flipped `allow_negative_stock` can corrupt stock integrity for weeks before anyone notices.

## Workflow

```
[Policy decision, e.g. "raise discount ceiling to 12%"]
                    │
                    ▼
[Open Settings → Sales category]
                    │
                    ▼
[Edit max_discount_without_approval: 10 → 12]
                    │
                    ▼
[Validation (type/range) → confirm dialog shows
 old value, new value, affected behaviour]
                    │
                    ▼
[Save → activity log entry → settings cache cleared]
                    │
                    ▼
[POS applies the new ceiling on the next transaction]
```

1. **Locate** the setting via category tabs or key search; each row shows key, current value, default, and a plain-language description.
2. **Edit** with a type-appropriate control (toggle for booleans, number input with bounds, select for enumerations like `fifo`/`avco`).
3. **Confirm** — high-impact keys (marked in the catalogue) require a confirmation restating the consequence.
4. **Propagate** — settings are cached; saving invalidates the cache so modules read the new value immediately.
5. **Audit** — every change logs key, old value, new value, user, timestamp to [Activity Logs](10.6-activity-logs.md).

| Screen | Route | Purpose |

**Layout**: left tab rail of the six categories; main pane lists each setting as a row — key, description, control, default badge, "modified" indicator where the value differs from default, and a per-row reset-to-default. A search box filters keys across all categories.

## Fields & Validation

Settings are typed; validation is per key. Representative rules:

| Setting | Type | Validation rules |
|---------|------|------------------|
| allow_negative_stock | boolean | high-impact: confirmation required |
| default_cost_method | enum | `fifo` or `avco`; locked once stock transactions exist |
| low_stock_alert_days | integer | 1–90 |
| quote_expiry_days | integer | 1–365 |
| max_discount_without_approval | decimal % | 0–100 |
| loyalty_earn_rate | decimal | >= 0, points per $1 |
| po_approval_threshold | decimal currency | >= 0 |
| grn_over_receive_tolerance | decimal % | 0–100 |
| job_card_reminder_mins | integer | 5–1440 |
| warranty_labour_rate | decimal currency | >= 0 |
| vat_rate_default | decimal % | 0–100 |
| ar_overdue_hold_days | integer | 0 (off) –365 |
| bank_rec_tolerance | decimal currency | 0–1.00 |
| email_on_* | boolean | — |

## Business Rules

1. Every setting has a coded default; deleting/rescinding a value reverts to the default rather than leaving a null.
2. `default_cost_method` is immutable once any stock movement exists — switching FIFO↔AVCO mid-history would corrupt valuations; a change requires a formal data migration outside this screen.
3. Branch-level overrides (currently `allow_negative_stock` on branches, [10.3](10.3-branch-management.md)) take precedence over the global key; the settings row states this and links to the branch screen.
4. Settings are read through a cached accessor; modules never hard-code the defaults, so the screen is the single source of truth.
5. Changes take effect for *new* actions only: raising `quote_expiry_days` does not extend already-issued quotes; documents store the values they were created under.
6. High-impact keys (`allow_negative_stock`, `allow_credit_over_limit`, `default_cost_method`, `vat_rate_default`) demand typed confirmation and are flagged in the audit log.
7. `vat_rate_default` here and on Company Setup must agree — the settings screen reads/writes the same underlying value to avoid divergence.
8. Unknown keys (from a newer code deploy) render read-only with their coded default until the catalogue metadata is updated.

## Edge Cases & Error Handling

- **Cache not invalidated on a multi-server deploy**: cache keys are versioned; a stale read window is bounded (e.g. 60 s TTL) so a missed invalidation self-heals.
- **Out-of-range value written directly to the DB**: accessor clamps/falls back to default and logs a warning, so a bad row cannot crash POS.
- **`ar_overdue_hold_days` lowered** (e.g. 60 → 30): accounts now past the new threshold go on hold at the next nightly evaluation, not retroactively mid-transaction; the confirm dialog states how many accounts will be affected.
- **Two admins editing the same key concurrently**: last save wins; both appear in the activity log with values, making the race reconstructable.
- **`vat_rate_default` changed while a POS session is open**: in-flight carts keep their rate; new carts pick up the new rate.
- **Loyalty expiry shortened**: points already issued keep their original expiry; only newly earned points use the new setting.
