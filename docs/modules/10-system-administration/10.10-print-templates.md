# 10.10 Print Templates

> Blade-to-PDF templates for every printed document, from A4 tax invoices to 80mm till receipts. Part of [Module 10: System Administration](../10-system-administration.md). **Status: new.**

## Purpose

Print Templates govern how SparesPro documents look on paper and in PDF: tax invoices, credit notes, quotations, purchase orders, delivery notes, job cards, account statements, GRNs, stock take sheets, and the 80mm thermal receipt. The engine is Laravel's native Blade, rendered to PDF via `barryvdh/laravel-dompdf` — one template file per document type under `resources/views/print/` (e.g. `invoice.blade.php`, `receipt-thermal.blade.php`).

Templates are where legal, brand, and practical requirements meet. Legal: a tax invoice must carry the company's VAT number, the customer's details, per-line VAT treatment, and the invoice number from [Number Sequences](10.9-number-sequences.md). Brand: logo, colours, footer text from [Company Setup](10.2-company-setup.md). Practical: a stock take sheet needs count columns and big bin locations; a job card needs the vehicle block (reg, make/model — "Toyota Hilux 2.8 GD-6", engine code, odometer) and signature lines; the thermal receipt must fit 42 characters across.

The admin screen manages template selection and preview; template *code* changes remain developer work, with the screen exposing safe customisation points (header/footer text, visibility toggles) rather than raw Blade editing.

## Workflow

```
[Developer builds/updates Blade template
 in resources/views/print/]
            │
            ▼
[Admin screen: template registered per
 document type, options configured
 (footer text, show/hide toggles, paper size)]
            │
            ▼
[Preview with sample data → sign off]
            │
            ▼
[User prints/emails a document anywhere
 in the system]
            │
            ▼
[Render pipeline: gather document data +
 company/branch data → Blade → dompdf → PDF]
            │
            ├──► [Download / print dialog]
            ├──► [Attach to email (10.11)]
            └──► [Archive copy stored with document]
```

1. **Author** — Blade templates receive a defined data contract (document, lines, company, branch, customer/supplier, totals).
2. **Configure** — per-document options: paper size (A4 / 80mm), copies wording ("Original"/"Copy"), footer text override, toggle blocks (banking details, signature lines, fitment notes).
3. **Preview** — render with realistic sample data (a Hilux brake-pad invoice, a multi-page statement) before go-live.
4. **Render** — every print/email path uses the same pipeline, so screen, email attachment, and archive PDF always match.
5. **Archive** — the generated PDF is stored against the document at posting, so reprints of historical documents show what was originally sent.

## Fields & Validation

Template options (per document type):

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| template_file | select | Yes | must exist in `resources/views/print/` |
| paper_size | select | Yes | A4 / A5 / 80mm-thermal (receipt only) |
| footer_text_override | textarea | No | falls back to company `invoice_footer_text` |
| show_banking_details | boolean | Yes | invoices/statements default true |
| show_signature_lines | boolean | Yes | delivery notes/job cards default true |
| copy_labels | text list | No | e.g. Original, Customer Copy, File Copy |
| logo enabled | boolean | Yes | default true |

Render-time validation: required data present (company VAT number for tax invoices), totals on the template equal document totals, and page rendering succeeded — failures block issuing rather than sending a broken PDF.

## Business Rules

1. Tax invoice and credit note templates must render the statutory block: company name, address, VAT number, document number, date, customer details, line VAT, VAT summary by rate, and totals — a template missing bound fields fails registration validation.
2. Archived PDFs are immutable: template changes affect future renders only; reprint of a posted document serves the archived copy, with "re-render with current template" as an explicit admin action.
3. The thermal receipt template is width-constrained (80mm/42 chars) and skips graphics-heavy elements; dompdf renders it with a fixed-width font.
4. All money formatting uses the document's currency and the currency's `decimal_places` from [10.12 Currencies](10.12-currencies.md).
5. Multi-page documents repeat the header/column row per page and show "Page X of Y"; statements and stock take sheets must paginate cleanly at any length.
6. Branch documents print the issuing branch's address/phone ([10.3](10.3-branch-management.md)) with company-level legal identity from [10.2](10.2-company-setup.md).
7. Job card templates include the vehicle block (registration, make/model/variant, engine code, odometer in/out) and customer-authorisation signature line.
8. Template option changes are activity-logged; template file changes are tracked in version control (developer workflow), and the screen shows the file's last-modified stamp.

## Edge Cases & Error Handling

- **Logo missing/corrupt at render time**: document renders without the logo rather than failing the print; a warning is logged.
- **Very long part descriptions** (cross-reference strings on a line): templates wrap within the description column; totals column alignment is fixed-width so numbers never shift.
- **Zero-VAT and mixed-VAT invoices**: the VAT summary block groups by rate, including a 0% line, so exempt/zero-rated sales print unambiguously.
- **dompdf unsupported CSS** (flexbox etc.): the template style guide restricts to table-based layouts; preview is the enforcement gate.
- **80mm receipt for an invoice with 60 lines**: thermal template has no page concept — it prints continuously; the POS offers A4 fallback for large sales.
- **Special characters in customer names** (diacritics): templates use a UTF-8-capable font, e.g. DejaVu Sans, bundled with dompdf.
- **Email attachment size** for a 200-page statement: rendering caps with a link-delivery fallback per [9.8](../09-reports-analytics/9.8-scheduled-reports.md) conventions.
