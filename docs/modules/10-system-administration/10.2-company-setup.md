# 10.2 Company Setup

> Legal identity, tax registration, and document defaults for the trading entity. Part of [Module 10: System Administration](../10-system-administration.md). **Status: existing, with motor-spares extensions planned.**

## Purpose

Company Setup holds the single record describing the business itself: trading name, logo, registration details, and — in the planned extensions — everything a tax invoice legally requires (VAT number, tax number), the financial calendar (`financial_year_start`), the default currency and VAT rate, document prefixes (INV/QT/PO), banking details for statements, and the invoice footer text.

Almost every printed document reads from this record: the letterhead block on an invoice, the VAT number that makes it a valid tax invoice, the banking details on a statement. Getting it wrong is not cosmetic — an invoice without the seller's VAT number can be rejected by a VAT-registered customer's auditors, and a wrong financial-year start misaligns every year-to-date report.

The existing implementation covers company details and logo; the extension adds the motor-spares/tax columns listed in the parent doc.

## Workflow

```
[Initial system setup]
        │
        ▼
[Enter legal identity: name, registration,
 VAT number, tax number, logo]
        │
        ▼
[Set financial calendar: financial_year_start
 (e.g. "01-01" or "07-01")]
        │
        ▼
[Set defaults: base currency, default VAT rate
 (e.g. 15.00), document prefixes INV/QT/PO]
        │
        ▼
[Enter banking details + invoice footer text]
        │
        ▼
[Documents, reports, and sequences consume
 these values from then on]
```

1. **Identity** — legal/trading name, company registration, logo upload (`logo_path`) used on all printed documents.
2. **Tax registration** — `vat_number` and `tax_number`; these print on tax invoices and credit notes.
3. **Financial calendar** — `financial_year_start` as MM-DD; drives financial-year boundaries in Finance and Reports.
4. **Defaults** — `default_currency_id` (see [10.12 Currencies](10.12-currencies.md)), `default_vat_rate`, and the document prefixes that seed [Number Sequences](10.9-number-sequences.md).
5. **Presentation** — `invoice_footer_text` ("Thank you for your business") and `banking_details` rendered by [Print Templates](10.10-print-templates.md).

## Fields & Validation

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| name | text | Yes | max 255 |
| vat_number | text | For VAT-registered | max 30; format check per jurisdiction if configured |
| tax_number | text | No | max 30 |
| financial_year_start | text | Yes | MM-DD pattern, valid month/day (e.g. "01-01", "07-01") |
| default_currency_id | select | Yes | active currency; becomes base currency |
| default_vat_rate | decimal | Yes | 0–100, two decimals (e.g. 15.00) |
| invoice_prefix / quote_prefix / po_prefix | text | Yes | max 10, uppercase alphanumeric |
| logo_path | image | No | png/jpg/svg, max 1 MB; recommended min width for print quality |
| invoice_footer_text | textarea | No | plain text/simple HTML |
| banking_details | textarea | No | bank, account name/number, branch code, SWIFT as free text |

## Business Rules

1. The company record is a singleton — there is exactly one, edited in place; multi-entity trading is out of scope (branches handle locations, [10.3](10.3-branch-management.md)).
2. The base currency (`default_currency_id`) cannot change once transactions exist (rule shared with [10.12 Currencies](10.12-currencies.md)).
3. Changing `financial_year_start` after go-live requires confirmation and takes effect from the *next* financial year; historical years keep their boundaries.
4. `default_vat_rate` is a default, not history: documents store the rate they were issued at, so changing the default never restates old invoices.
5. Document prefixes here are the defaults consumed by [Number Sequences](10.9-number-sequences.md); once a sequence has issued numbers, its prefix changes are managed there, not here.
6. VAT number changes are activity-logged with before/after values — this field has statutory weight.
7. Logo replacement affects future document renders only; archived PDFs keep the logo they were generated with.
8. Banking details print on statements and invoices; edits require the Accountant or higher role because a fraudulent bank-detail swap is a classic invoice-fraud vector.

## Edge Cases & Error Handling

- **Business not yet VAT-registered, registers later**: leave `vat_number` blank initially; on entry, invoices automatically switch to tax-invoice format from that date. Historic non-VAT invoices are not reissued.
- **Logo file uploaded at low resolution**: warning with a print preview so the admin sees the pixelation before committing.
- **Financial year change requested mid-year**: blocked for the current year; the form schedules it for the next year boundary and shows the effective date.
- **Prefix collision** (invoice_prefix changed to match po_prefix): warned — duplicate prefixes make document references ambiguous for humans even though sequences remain distinct.
- **Banking details edited**: confirmation dialog restates old and new values; change alert email to the owner (planned) mitigates fraud risk.
- **Footer text with unsupported HTML**: sanitised on save; the preview shows exactly what will print.
