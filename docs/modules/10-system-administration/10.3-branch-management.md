# 10.3 Branch Management

> Physical locations — where stock is held, sales happen, and workshops operate. Part of [Module 10: System Administration](../10-system-administration.md). **Status: existing, with extensions planned.**

## Purpose

Branches are the operational unit of SparesPro: every stock quantity, sale, GRN, and job card belongs to a branch. Branch Management defines those locations and their capabilities. The planned extensions add the flags and defaults the spares workflows depend on: `is_warehouse` (can this branch hold stock?), `is_workshop` (does it run bays?), `is_head_office`, a `branch_code` used in document numbering, a `default_price_list_id` (city and rural branches may price differently), a per-branch `allow_negative_stock` override, and a `gl_profit_centre_id` so Finance can produce a per-branch P&L.

Branch records also feed printed documents — a customer invoice shows the issuing branch's address and phone — and they are the scoping dimension for permissions: a Branch Manager's reports, stock views, and dashboards are constrained to their branch (see [10.1](10.1-users-roles.md)).

## User Roles & Permissions

| Role | Access |
|------|--------|
| Super Admin | Full CRUD |

## Workflow

```
[New location opening]
        │
        ▼
[Create branch: name, branch_code, address,
 phone, email]
        │
        ▼
[Set capability flags: is_warehouse,
 is_workshop, is_head_office]
        │
        ▼
[Set defaults: price list, allow_negative_stock,
 GL profit centre]
        │
        ▼
[Seed per-branch number sequences (10.9)]
        │
        ▼
[Assign users to the branch (10.1)]
        │
        ▼
[Branch live: stock, sales, reports scoped to it]
```

1. **Create** the branch with identity and contact details; `branch_code` (e.g. `HRE`, `BYO`) becomes part of document numbers where sequences are branch-scoped.
2. **Flag capabilities** — warehouse-only depots take no sales; workshop flag switches on job-card features and workshop reports for the branch.
3. **Set defaults** — price list for POS, negative-stock override, profit centre for the branch P&L.
4. **Wire numbering** — per-branch sequences in [10.9](10.9-number-sequences.md) if numbers should carry the branch code.
5. **Operate** — all transactional modules stamp the branch; reports and dashboards filter by it.

## Fields & Validation

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| name | text | Yes | max 255, unique |
| branch_code | text | Yes | 2–10 uppercase alphanumeric, unique, immutable after documents exist |
| address | textarea | Yes | prints on documents |
| phone | text | No | max 20 |
| email | email | No | valid format |
| is_warehouse | boolean | Yes | default true |
| is_workshop | boolean | Yes | default false |
| is_head_office | boolean | Yes | only one branch may hold it |
| default_price_list_id | select | Yes for selling branches | active price list |
| allow_negative_stock | boolean | Yes | default from the global setting |
| gl_profit_centre_id | select | No | valid GL profit centre |

## Business Rules

1. Exactly one branch may be head office; setting the flag on another branch prompts to move it.
2. `branch_code` is immutable once any document number embeds it — renaming would orphan document references.
3. A branch with `is_warehouse = false` cannot receive stock or hold quantities; transfers to it are blocked at source.
4. Turning `is_workshop` off is blocked while open job cards exist at the branch.
5. Per-branch `allow_negative_stock` overrides the global setting in [10.5](10.5-system-settings.md); the *stricter* interpretation applies when the global forbids it (global false + branch true still allows it only if the implementation defines branch as authoritative — the setting screen states the precedence explicitly: branch overrides global).
6. Deactivating a branch requires: zero stock on hand, no open documents (sales orders, POs, job cards, transfers). The pre-check lists blockers.
7. Deactivated branches remain in historical reports and document headers.
8. Every user belongs to a branch; branch deactivation forces reassignment of its active users.
9. `gl_profit_centre_id` is required before the branch appears in the per-branch P&L; unmapped branches roll into "Head Office/unallocated" (see [9.4](../09-reports-analytics/9.4-financial-reports.md)).

## Edge Cases & Error Handling

- **Branch relocation** (address change, same business): edit in place — documents already issued keep their printed address in archived PDFs; new documents pick up the new address.
- **Two branches in one city needing distinct codes** (e.g. `HRE1`, `HRE2`): supported; codes just need uniqueness.
- **Stock found at a branch being closed**: deactivation blocked; the pre-check links to a transfer-out worksheet to drain remaining stock.
- **Sales attempted at a warehouse-only depot**: POS routes are hidden for the branch; direct API attempts fail validation.
- **Workshop flag enabled later**: workshop menus, sequences (job cards), and reports light up for the branch; no migration needed.
- **Head-office flag moved while statements print head-office banking details**: documents always read banking details from Company Setup, not the branch, so the move is safe.
