# 10.9 Number Sequences

> Configurable, gap-safe numbering for every document type in the system. Part of [Module 10: System Administration](../10-system-administration.md). **Status: new.**

## Purpose

Every document SparesPro issues — invoices, quotes, POs, GRNs, job cards, credit notes, transfers, technical bulletins — needs a unique, human-readable number. Number Sequences centralises how those numbers are built: prefix, optional date component, zero-padded counter, optional suffix, per-branch scoping, and periodic reset. Examples from the parent doc: `INV-20260101-00042` (invoice, full date, 5-digit counter), `JC-2026-00107` (job card, year only), `PO-0089` (no date, 4-digit).

The stakes are higher than aesthetics. Tax authorities expect invoice numbers to be sequential and unbroken; auditors read gaps as deleted sales. Branch-scoped sequences (embedding `branch_code`, see [10.3](10.3-branch-management.md)) let each location number independently without collisions. And the generator must be concurrency-safe: two cashiers invoicing simultaneously must never draw the same number.

## Workflow

```
[Define sequence per document type
 (optionally per branch)]
        │
        ▼
[Format: prefix + date part? + padded counter
 + suffix?  e.g. INV-{Ymd}-{00000}]
        │
        ▼
[Document created anywhere in the system]
        │
        ▼
[Generator: lock row → read next_number →
 apply reset check (yearly/monthly) →
 format → increment → release]
        │
        ▼
[Number stamped on document, immutable]
```

1. **Define** — one sequence per `type` (`invoice`, `quote`, `po`, `grn`, `job_card`, `credit_note`, …), optionally per branch (`branch_id` null = global).
2. **Format** — prefix (defaults seeded from [Company Setup](10.2-company-setup.md) prefixes), `include_date` with `date_format` (`Ymd`, `Ym`, `Y`), `padding` width, optional suffix.
3. **Reset** — `reset_frequency` (`never`/`yearly`/`monthly`): at each boundary the counter returns to 1 and `last_reset_at` records it; the date component keeps reset numbers globally unique.
4. **Generate** — modules request "next number for type X at branch Y"; the generator is atomic (row lock or equivalent) and stamps the document.
5. **Adjust** — counter changes (e.g. continuing from a legacy system at 5001) are admin actions with justification, logged.

## Fields & Validation

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| type | select | Yes | known document type; unique per type+branch |
| branch_id | select | No | active branch; null = global; a global and branch sequence for the same type cannot both be active |
| prefix | text | Yes | max 10, uppercase alphanumeric + hyphen |
| include_date | boolean | Yes | — |
| date_format | select | If include_date | `Ymd`, `Ym`, `Y` |
| suffix | text | No | max 10 |
| next_number | integer | Yes | >= 1; edits beyond +1 of current require confirmation + reason |
| padding | integer | Yes | 3–8 |
| reset_frequency | select | Yes | `never`, `yearly`, `monthly` |

Cross-field: `reset_frequency` of `yearly`/`monthly` requires a date component at least as fine (`Y` for yearly, `Ym` or finer for monthly) so reset numbers cannot collide with earlier periods.

## Business Rules

1. Number generation is atomic — the counter row is locked for the read-increment-write, so concurrent documents can never share a number.
2. Numbers are consumed at document *posting*, not at form-open, so abandoned drafts do not burn numbers (financial document types); operational types (job cards) may consume at creation — the sequence config states which.
3. Issued numbers are immutable and never reused, including after document cancellation — a cancelled invoice keeps its number with status "cancelled", preserving the unbroken audit sequence.
4. Format changes (prefix, padding, date) apply to future numbers only; the change is activity-logged with before/after.
5. Reducing `next_number` below the highest issued number for the current period is blocked — it would mint duplicates.
6. Per-branch sequences take precedence over a global sequence of the same type; enabling a branch sequence mid-stream starts its counter where the admin sets it, with a collision check against numbers already issued globally.
7. Padding overflow (counter exceeds padding width, e.g. 100000 in a 5-digit format) does not truncate — the number grows a digit and the sequence is flagged for reconfiguration.
8. Reset execution is lazy and safe: the first generation after a boundary performs the reset inside the same lock.

## Edge Cases & Error Handling

- **Migration from a legacy system**: set `next_number` to legacy max + 1 with the confirmation flow; the reason is stored for the auditor.
- **Two servers/queue workers generating simultaneously**: DB-level locking guarantees uniqueness; retries on lock timeout are transparent to the user.
- **Backdated document after a yearly reset** (January entry dated December): the number uses the sequence current at posting time; the document date and number date component may legitimately differ — reports key on document date.
- **Sequence accidentally deleted/missing for a type**: generation fails closed with an explicit "no sequence configured for credit_note at branch BYO" error rather than silently inventing a format.
- **Branch code renamed** — prevented upstream: `branch_code` is immutable once used in numbers ([10.3](10.3-branch-management.md)).
- **Duplicate detected on insert** (constraint violation from a mis-set counter): the transaction rolls back, the generator re-draws, and the incident is logged.
