# 8.7 Technical Bulletins

> Fitment warnings, recall notes, and service advisories surfaced exactly where staff need them. Part of [Module 8: Vehicle & Parts Reference](../08-vehicle-parts-reference.md).

## Purpose

Some knowledge does not fit in a fitment table: "Bosch injectors for the Hilux 2.8 2016 — use part W800 not W750, W750 was recalled Jan 2023"; "aftermarket EBC pads on the Fortuner may cause ABS sensor interference". This tribal knowledge normally lives in the heads of one or two senior counter staff and walks out the door when they do. Technical bulletins capture it as structured, searchable records tied to the makes, models, and parts they affect.

The value is in *placement*: a bulletin is only useful if it appears at the moment of decision. A critical bulletin attached to a part must interrupt the sale of that part for an affected vehicle; a warning bulletin should show inline in fitment results; an info bulletin should be available one click away. Staff should never have to remember to go look.

Bulletins also give the business a defensible record for recalls and safety issues — who was warned, when the bulletin was issued, and what the prescribed resolution was.

## User Roles & Permissions

| Role | Access |
|------|--------|
| Super Admin | Full CRUD |
| Data Administrator | Create/edit/deactivate bulletins |
| Sales Manager | Create/edit bulletins; approve critical ones |
| Workshop Foreman | Create draft bulletins from workshop findings |
| Cashier / Counter Staff | View; must acknowledge critical bulletins at POS |
| Technician | View on job cards |

## Workflow

```
[Trigger: supplier recall / workshop comeback / OEM notice]
                    │
                    ▼
        [Draft bulletin: title, description,
         severity, resolution, source]
                    │
                    ▼
        [Tag affected makes / models / parts]
                    │
                    ▼
      [severity = critical? → Sales Manager approval]
                    │
                    ▼
              [Publish (active)]
                    │
      ┌─────────────┼──────────────────┐
      ▼             ▼                  ▼
[Inline banner  [POS interrupt    [Bulletin list
 in fitment      on affected       searchable by
 results]        part+vehicle      part/vehicle]
                 combos]
                    │
                    ▼
        [Issue resolved → deactivate, kept for history]
```

1. **Draft** — anyone with create rights writes the bulletin with an auto-assigned number (`TB-YYYY-XXX`).
2. **Tag** — attach affected make(s), model(s), and part(s); tags drive where the bulletin surfaces.
3. **Approve** — `critical` bulletins require sales-manager approval before going active (they interrupt selling).
4. **Surface** — active bulletins appear in fitment results, part detail, POS, and job cards for matching combinations.
5. **Retire** — once superseded stock is purged or the issue lapses, deactivate; the record and its acknowledgements remain.

## Screens

| Screen | Route | Purpose |
|--------|-------|---------|
| Bulletins list | `vehicle-ref.bulletins.index` | All bulletins, filter by severity/status/make/part |
| Bulletin create/edit | `vehicle-ref.bulletins.create` / `.edit` | Authoring form |
| Bulletin detail | `vehicle-ref.bulletins.show` | Full text, tags, acknowledgement log |

**Primary screen — Bulletins list** (`VehicleRef/Bulletins/Index.jsx`): table of bulletin number, title, severity badge (grey info / amber warning / red critical), affected summary ("Toyota Hilux, Fortuner — 3 parts"), issue date, source, active toggle. Filters across the top; critical actives pinned to the top of the list.

## Fields & Validation

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| bulletin_number | auto | Yes | pattern `TB-YYYY-XXX`, generated via number sequences, immutable |
| title | text | Yes | max 255 |
| description | rich text | Yes | the problem statement |
| severity | select | Yes | `info`, `warning`, `critical` |
| affected_makes | multi-select | No | at least one of makes/models/parts must be tagged |
| affected_models | multi-select | No | models must belong to selected makes if both given |
| affected_parts | multi-select | No | active or superseded parts |
| issue_date | date | Yes | defaults today; not in the future |
| resolution | text | Yes | what staff must do (e.g. "supply W800; quarantine W750 stock") |
| source | text | No | max 100 (e.g. "Bosch SA recall notice") |
| is_active | boolean | Yes | default false until approved/published |

## Business Rules

1. A bulletin with no tags at all cannot be published — untargeted bulletins would surface nowhere.
2. `critical` bulletins interrupt POS: selling a tagged part for a tagged vehicle requires the cashier to acknowledge the bulletin (logged with user and timestamp) before the line is added.
3. `warning` bulletins render as an amber banner in fitment results and part detail; `info` bulletins as an expandable note.
4. Critical bulletins require approval by a Sales Manager or Super Admin; the approver is recorded.
5. Bulletins referencing a recalled part should be paired with a stock action (quarantine/return) in Inventory — the bulletin links to the stock adjustment reference in `resolution`.
6. Deactivated bulletins stop surfacing immediately but remain searchable and keep their acknowledgement history.
7. Matching is by tag intersection: a bulletin tagged (Hilux model) + (part W750) fires only when both sides match the transaction context; tagged parts alone fire on any sale of that part.
8. Editing an active critical bulletin re-triggers acknowledgement for all users (previous acks are versioned, not erased).

## Edge Cases & Error Handling

- **Bulletin about a part the shop no longer stocks**: still publishable — customers may bring the part in, and workshop may encounter it fitted.
- **Model tagged without make consistency** (model belongs to a different make than tagged): form blocks save and highlights the mismatch.
- **Bulk sale (20 filters) with one critical bulletin**: single acknowledgement covers the line, not per unit.
- **Bulletin fires on a superseded part**: the notice follows the chain — selling the replacement for an affected vehicle still shows the bulletin if the replacement is tagged; if only the old part is tagged, resolution text should say whether the new part clears the issue.
- **Two active critical bulletins on one combo**: both must be acknowledged; the POS dialog stacks them.
- **Cashier declines to acknowledge**: line is not added; the decline is not logged as a sale block reason but the attempted-add is visible in activity logs.
- **Historic reporting after deactivation**: acknowledgement log is queryable for "who sold W750 after the recall date" investigations.
