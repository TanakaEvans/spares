# 8.4 Fitment Guide

> Answers "what parts fit this vehicle?" at the counter, in the workshop, and online. Part of [Module 8: Vehicle & Parts Reference](../08-vehicle-parts-reference.md).

## Purpose

The Fitment Guide is the vehicle-first search path: pick (or look up) a vehicle and the catalogue filters down to compatible parts. It is the inverse of [cross-reference search](8.3-parts-cross-reference.md), which is number-first. Together they cover the two ways customers actually ask: "have you got this number?" and "what do you have for a Hilux 2.8?".

Fitment data is what prevents the most expensive kind of mistake in a spares business: selling a part that does not fit. A wrong filter or brake pad costs a return trip, a credit note, restocking, and customer trust — and in the workshop it costs a bay-hours redo. Every fitment record therefore carries a confidence level (Confirmed / Likely / Verify) so staff know when to double-check before committing.

The registration-lookup flow makes fitment fast for repeat customers: once a customer's Toyota Hilux 2.8 GD-6 is registered against their account, scanning the registration at POS instantly filters the catalogue for that exact variant — no make/model questioning needed.

## Workflow

```
[Customer at POS]
      │
      ▼
[Scan / type vehicle registration]
      │
      ├── found in customer_vehicles ──► [Variant known]
      │                                        │
      └── not found ──► [Select make → model → │year → variant manually]
                                               ▼
                                   [Catalogue filtered to fitting parts]
                                               │
                                               ▼
                          [Each result shows confidence: ✓ Confirmed
                           ~ Likely   ? Verify]
                                               │
                                               ▼
                               [Add to sale / job card]
```

1. **Identify the vehicle** — registration lookup against `customer_vehicles`, or manual make/model/year/variant selection.
2. **Filter** — the parts catalogue is restricted to parts with a fitment record matching the variant (or its model, at lower confidence).
3. **Assess confidence** — ✓ Confirmed (verified fit), ~ Likely (model-level or inferred data), ? Verify (conflicting or incomplete data, or grey-import region mismatch).
4. **Sell/issue** — the part goes onto the invoice or job card; the vehicle context is stored on the line for later returns analysis.
5. **Feed back** — a technician who physically confirms a "~ Likely" fit can promote it; a counter return for wrong fitment flags the record for review.

**Primary screen — Fitment lookup** (`VehicleRef/Fitment/Index.jsx`): top bar with registration input plus cascading make → model → year → variant selectors; below, category chips (Filters, Brakes, Suspension, Service Kits…) and the filtered parts grid. Each card/row shows part, brand, price, branch stock, and the confidence badge. Example result set for a Hilux 2.8 GD-6 (2020): Mann HU7028z oil filter ✓, Ryco A1787 air filter ✓, Gates K025475XS timing kit ~, Ferodo FDB4473 front pads ✓.

## Fields & Validation

Fitment record (part ↔ vehicle link):

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| part_id | select | Yes | active part |
| variant_id | select | Conditionally | either variant_id or model_id required |
| model_id | select | Conditionally | used for model-wide fitments; mutually informative with variant |
| year_from / year_to | integer | No | narrows within the variant's own years; year_to >= year_from |
| position / qualifier | text | No | max 100, e.g. "Front", "Left", "From VIN #####" |
| confidence | select | Yes | `confirmed`, `likely`, `verify` |
| source | text | No | max 100, e.g. "TecDoc 2025Q2", "Verified in workshop JC-2026-00107" |

## Business Rules

1. Variant-level fitments outrank model-level ones; when both exist for a search, only the variant-level answer is shown.
2. A model-level fitment can never display as ✓ Confirmed — confirmation requires a variant-level record.
3. Duplicate fitments (same part + same variant + overlapping years + same position) are blocked.
4. Fitment confidence is displayed everywhere the part is offered against a vehicle: POS, quotations, workshop parts issue.
5. A return processed with reason "wrong fitment" automatically drops the record's confidence to `verify` and queues it for review.
6. Superseded parts inherit their successor's visibility: the fitment search returns the *current* part in a chain, never a superseded number (see [8.6](8.6-supersession-management.md)).
7. Region mismatches (part fitment sourced for `europe`, vehicle variant is `southern_africa`) cap confidence at ~ Likely.
8. Bulk fitment imports (TecDoc / ACES) load as `likely` by default; only explicit verification promotes to `confirmed`.

## Edge Cases & Error Handling

- **Registration not found and customer doesn't know the variant**: model + year search returns the union of all variants' parts; items differing between variants show ? Verify with the differing engine codes listed ("2GD-FTV vs 1GD-FTV — check engine").
- **Registration found but vehicle was sold/changed**: staff can detach the vehicle from the customer and fall back to manual selection; the stale link is flagged, not silently reused.
- **Part fits only after a VIN break**: use the qualifier field ("From VIN…") and a linked [technical bulletin](8.7-technical-bulletins.md); confidence stays `verify` because the system cannot check VIN.
- **No fitment data at all for a vehicle** (new Chinese model, e.g. a recent Chery): screen shows an explicit "no fitment data yet" state with a link to request catalogue data — never an empty grid that reads as "we stock nothing".
- **Conflicting imported data** (two sources disagree): both records kept, both surfaced as ? Verify, review-queue entry created for the data admin.
- **Technician confirms a fit on a grey import**: promotion to `confirmed` is allowed but records the source job card for traceability.
