# 8.3 Parts Cross-Reference

> Find the right part no matter which number the customer walks in with. Part of [Module 8: Vehicle & Parts Reference](../08-vehicle-parts-reference.md).

## Purpose

A single oil filter can carry dozens of identities: the OEM number Toyota prints on the box (90915-YZZD3), the aftermarket manufacturer's own number (Mann HU 7028 z), a competitor's catalogue code, and an EAN barcode. Customers arrive with whichever one they have — a number read off the old part, a Toyota dealer quote, or a screenshot of a rival's website. Cross-referencing lets counter staff type any of those numbers and land on the stocked part.

Commercially, this is the difference between a sale and a walk-out. If a customer quotes the Toyota OEM number and the shop stocks the Mann equivalent at 60% of the dealer price, cross-reference search surfaces it instantly and the cashier can quote the aftermarket option with confidence. Without it, the answer is "we don't stock that", which is often false.

The cross-reference set also feeds purchasing (matching a supplier's price file numbers to internal parts) and supersession handling ([8.6](8.6-supersession-management.md)), which is stored as a cross-reference type of its own.

## Workflow

```
[Customer quotes a number] → [Cross-ref search]
                                   │
                 ┌─────────────────┼──────────────────┐
                 ▼                 ▼                  ▼
          [Exact match]     [Superseded number]  [No match]
                 │                 │                  │
                 ▼                 ▼                  ▼
        [Open stocked part]  [Redirect to        [Offer fitment
         with stock & price   current part +      lookup by vehicle
         at this branch]      supersession        instead]
                              notice]
```

1. **Search** — staff type or scan any number; matching is normalised (case, spaces, hyphens stripped) so `90915YZZD3` finds `90915-YZZD3`.
2. **Resolve** — the system returns the internal part(s) linked to that number, with the cross-reference type shown (OEM / aftermarket / competitor / EAN).
3. **Supersession redirect** — a `superseded_by` hit follows the chain (see [8.6](8.6-supersession-management.md)) and opens the current part with a notice.
4. **Maintain** — data admins attach new numbers to parts as they are discovered (supplier catalogues, TecDoc import, counter feedback).
5. **Bulk import** — CSV/TecDoc loads of number pairs, validated against existing parts.

## Fields & Validation

Adding a cross-reference to a part:

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| part_id | (context) | Yes | the internal part being annotated |
| reference_number | text | Yes | max 50; normalised copy stored for matching; unique per part+type |
| type | select | Yes | one of `oem`, `aftermarket`, `superseded_by`, `competitor`, `ean` |
| brand / source | text | Conditionally | required for `aftermarket` (e.g. "Mann") and `competitor` (e.g. "GSF") |
| notes | text | No | max 255 (e.g. "verified against Toyota EPC 2024") |

EAN entries additionally validate as 8 or 13 digits with a correct check digit.

## Business Rules

1. Matching is always on the normalised form (uppercase, alphanumeric only); the original formatting is preserved for display.
2. One reference number may legitimately map to multiple internal parts (a competitor code covering a kit); search then lists all matches rather than guessing.
3. `superseded_by` entries are maintained through the supersession sub-module, not edited freehand here — this keeps chains consistent.
4. A part's own internal part number and its primary OEM number are both searchable through the same box; internal numbers win rank when both match.
5. Competitor numbers are never printed on customer documents — they exist for lookup only.
6. Bulk imports validate that the target part exists; unmatched rows go to an exception list for manual resolution instead of creating orphan references.
7. Removing a cross-reference is logged (who/when) because a deleted reference silently degrades search and is otherwise hard to diagnose.

## Edge Cases & Error Handling

- **Same OEM number reused by two manufacturers** (rare but real for short numeric codes): results show the make/brand column so staff can disambiguate; nothing auto-selects.
- **Customer's number matches a part stocked at another branch only**: result shows zero on-hand locally with per-branch availability, enabling an inter-branch transfer offer.
- **Scanned EAN with wrong check digit** (damaged barcode): exact search fails; the system falls back to a fuzzy suggestion list ("did you mean 4025533041001?").
- **Number matches only a superseded chain whose end part is inactive**: the notice states the line is discontinued with no active replacement; staff pivot to [fitment lookup](8.4-fitment-guide.md).
- **Import creates a circular pair** (A cross-refs B, B cross-refs A as `superseded_by`): rejected by the supersession chain validator.
- **Whitespace/OCR garbage in search input** (`O` vs `0`): normalisation plus a 1-character-tolerance fuzzy pass keeps the counter moving.
