# 1.1 Parts Catalogue

> Master data for every part the business stocks — SKU, descriptions, brands, barcodes, cross-references, and supersessions. Part of [Module 1: Inventory Management](../01-inventory-management.md).

## Purpose

The parts catalogue is the single source of truth for every part the business stocks or has ever stocked. Every other record in the system — a stock level, an invoice line, a purchase order, a fitment entry — hangs off a row in the `parts` table. A clean catalogue means a fast counter: when a customer walks in asking for "the oil filter for a 2018 Hilux 2.8 GD-6", staff must resolve that to internal part number `FLT-OIL-0451` (e.g. a Toyota OEM `90915-YZZD4` or its Fram cross-reference `PH10075`) in seconds.

The catalogue also solves the cross-reference problem that defines the spares trade: the same physical part is known by an internal number, one or more OEM numbers, and several aftermarket brand numbers. Customers arrive with any one of these. Without a maintained cross-reference table, staff fall back on memory and lose sales when the person who "knows the numbers" is off shift.

Finally, the catalogue manages supersession. Manufacturers regularly replace part numbers (e.g. Toyota supersedes `90915-YZZD2` with `90915-YZZD4`). Old numbers must keep resolving to the current stocked part, otherwise stock appears unavailable when it is sitting on the shelf under the new number.

| Role | Access |
|------|--------|
| Cashier / Counter Sales | View and search parts; no edits |
| Storeman | View; edit bin-related fields only |
| Inventory Clerk | Create and edit parts, images, cross-references |
| Inventory Manager | Full access including supersessions, discontinue, soft delete |
| Branch Manager | Full access within branch context |
| System Admin | Full access, restore soft-deleted parts, merge duplicates |

## Workflow

```
New part arrives from supplier / new line decision
        │
        ▼
Create part (number, description, category, brand, UoM)
        │
        ▼
Add barcodes + cross-references (OEM + aftermarket numbers)
        │
        ▼
Add images, dimensions, weight
        │
        ▼
Link fitments (see 1.6) ──► Set pricing (Module 2.6) ──► Set reorder levels (1.5)
        │
        ▼
Part is Active → appears in POS search and purchasing
        │
        ├──► Superseded → old number redirects to new part
        └──► Discontinued → blocked from new POs, kept for history
```

1. Inventory Clerk creates the part with the minimum required fields; part number is validated for uniqueness on blur.
2. Clerk records the OEM number and any known aftermarket cross-references so counter search works from day one.
3. Barcode is captured by scanning the supplier box label (EAN-13) or generating an internal Code 128 label.
4. Images, weight, and dimensions are added (weight/dimensions feed freight quotes on deliveries).
5. Fitments, price list entries, and reorder points are configured via their own sub-modules.
6. When the manufacturer supersedes the number, the clerk records a supersession; when the line is dropped, the manager marks it discontinued.

A supersession banner appears across the top if this part supersedes or is superseded by another.

## Fields & Validation

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| part_number | string(50) | Yes | Unique system-wide; uppercase on save; no spaces; regex `[A-Z0-9\-\.\/]+` |
| description | string(255) | Yes | Min 5 chars |
| short_description | string(100) | Yes | Shown on POS and labels; min 3 chars |
| oem_number | string(100) | No | Unique per brand, not globally |
| category_id | FK | Yes | Must be an active leaf or mid-level category |
| brand_id | FK | Yes | Must be active brand |
| unit_of_measure_id | FK | Yes | e.g. each, pair, set, litre |
| barcode_ean | string(20) | No | Valid EAN-13 check digit; unique if present |
| barcode_code128 | string(50) | No | Unique if present |
| weight_kg | decimal(8,3) | No | > 0 when present |
| length/width/height_cm | decimal(8,2) | No | > 0 when present |
| is_oem | boolean | Yes | Defaults false (aftermarket) |
| has_serial_tracking | boolean | Yes | Cannot be turned OFF once serialised stock exists |
| has_batch_tracking | boolean | Yes | Same lock rule as serial tracking |
| is_special_order | boolean | Yes | Special-order parts skip reorder alerts |

## Business Rules

1. Part number is unique across the system; comparison is case-insensitive and ignores stray whitespace.
2. Searching a superseded number must surface the replacement part with an explicit "superseded by FLT-OIL-0452" warning — never a silent redirect, because the old part may still hold sellable stock.
3. Supersession chains (A→B→C) resolve to the final active part; the chain is displayed so staff can also sell remaining stock of intermediate numbers.
4. Discontinued parts cannot be added to new purchase orders but can still be sold until stock reaches zero.
5. A part with stock on hand at any branch, open documents, or ledger history cannot be hard-deleted — only soft-deleted, and soft delete is blocked while stock on hand > 0.
6. `oem_number` uniqueness is per-brand: Bosch `0986452041` and a different brand's identical string may coexist.
7. Enabling `has_serial_tracking` on a part that already has untracked stock requires a stock take on that part first, so every unit gets a serial captured.
8. Changing `unit_of_measure` is blocked once ledger history exists (it would corrupt quantity history); create a new part instead.
9. Duplicate detection: on create, the system warns if the OEM number or EAN already exists on another part, but allows override with a reason (genuine shared barcodes exist on multi-packs).

## Edge Cases & Error Handling

- **Barcode scan returns nothing at POS**: search falls through to cross-reference numbers, then supersession history, before showing "not found — create special order?".
- **Two clerks create the same part simultaneously**: the unique index on `part_number` rejects the second insert; the form surfaces "part already exists" with a link to the winner.
- **Supersession loop entered (A→B, B→A)**: validation walks the chain on save and rejects any cycle.
- **Image upload fails mid-save**: part saves without the image; gallery shows a retry option rather than failing the whole form.
- **Part marked discontinued while on an open draft PO**: the PO line is flagged at review time; posting the PO with a discontinued part is blocked.
- **EAN with bad check digit scanned from supplier box**: stored only after user confirms "save as raw code" into `barcode_code128` instead of `barcode_ean`.
- **Restore of a soft-deleted part** whose number was since reused: restore is blocked; admin must rename one of them.
