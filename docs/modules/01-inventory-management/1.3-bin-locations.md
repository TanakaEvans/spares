# 1.3 Bin Locations

> Addressable warehouse locations (Aisle → Row → Shelf → Bin) and part-to-bin assignments. Part of [Module 1: Inventory Management](../01-inventory-management.md).

## Purpose

Bin locations turn a warehouse of steel shelving into an addressable grid. Every shelf position gets a code like `A-3-B-07` (aisle A, row 3, shelf B, bin 07) with a scannable barcode label. Parts are assigned to bins, so a picker who has never handled a Hilux wheel bearing (`SUS-WBR-0233`) can still find it: the pick slip says `C-2-A-15` and they walk straight to it.

Without bins, picking speed depends on tribal knowledge — the storeman who knows that NGK plugs live "on the shelf behind the counter, third box up". That knowledge leaves with staff turnover and breaks entirely when a second branch opens. Bin codes also make putaway deterministic: a goods receipt for 24 Castrol 5W-30 5L bottles prints a putaway list pointing at the primary bin `E-1-D-02`, plus an overflow bin if the primary is full.

Finally, bins are the unit of work for cycle counts. A weekly cycle count of "aisle A" is only possible if the system knows which parts should be in aisle A. Bin-level quantities (`qty_in_bin`) let variances be localised to a shelf rather than a whole branch.

## User Roles & Permissions

| Role | Access |
|------|--------|
| Cashier | View a part's bin code at POS (to direct customers/pickers) |
| Storeman | Assign/move parts between bins, print bin labels, update `qty_in_bin` via moves |
| Inventory Clerk | Create/edit bin locations, manage assignments |
| Inventory Manager | Full access; deactivate bins; bulk re-binning tools |
| System Admin | Full access across branches |

## Workflow

```
Define warehouse layout (aisles, rows, shelves, bins per branch)
        │
        ▼
Generate bin codes + print barcode labels ──► fix labels to shelving
        │
        ▼
Assign parts to bins (one primary + optional overflow bins)
        │
        ▼
Daily use:
  GRN putaway list → putaway to primary (overflow if full)
  Pick slip → pick from primary first, then overflow
  Bin-to-bin move → storeman scans from-bin, part, to-bin
        │
        ▼
Cycle counts select bins → count sheet loads that bin's expected parts
```

1. Inventory Clerk models the physical layout once per branch; bulk generation creates a range (e.g. aisle A, rows 1–6, shelves A–D, bins 01–20).
2. Labels with Code 128 barcodes are printed and fixed to shelving.
3. Each stocked part gets a primary bin; fast movers get an overflow bin for bulk stock.
4. Receiving prints a putaway list sorted by bin walk sequence; picking prints pick slips sorted the same way to minimise walking.
5. Storeman performs bin-to-bin moves by scanning: from-bin barcode → part barcode → to-bin barcode → quantity.

## Screens

| Screen | Route | Purpose |
|--------|-------|---------|
| Bin locations | `inventory.bins.index` | Branch bin map: browse, create, print labels |
| Bin detail | `inventory.bins.show` | Parts in this bin with quantities; move actions |
| Part detail (bins tab) | `inventory.parts.show` | Bin assignments for one part across branches |

**Primary screen — Bin locations (`Bins/Index.jsx`):** Header holds the branch selector, a search box (accepts a bin code or scanned barcode), and actions: New Bin, Bulk Generate, Print Labels. Main area is a collapsible tree grouped by aisle → row, each bin showing its code, number of assigned parts, and total quantity; empty and inactive bins are visually muted. Selecting a bin opens a side panel listing its parts (`qty_in_bin` each) with Move and Count actions.

## Fields & Validation

Main form: bin location.

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| branch_id | FK | Yes | Active branch |
| aisle | string(10) | Yes | Uppercase alphanumeric |
| row | string(10) | Yes | Alphanumeric |
| shelf | string(10) | Yes | Alphanumeric |
| bin | string(10) | Yes | Alphanumeric; zero-padded recommended ("04") |
| full_code | string(30) | Auto | Generated `AISLE-ROW-SHELF-BIN`; unique per branch |
| barcode | string(50) | Auto | Generated Code 128; unique |
| is_active | boolean | Yes | Default true |

Part-bin assignment form:

| Field | Type | Required | Validation rules |
|-------|------|----------|------------------|
| part_id | FK | Yes | Active part |
| bin_location_id | FK | Yes | Active bin, same branch as the assignment |
| is_primary | boolean | Yes | Exactly one primary per part per branch (enforced) |
| qty_in_bin | decimal(10,2) | Auto | Maintained by moves/receipts/picks, not hand-typed |

## Business Rules

1. A part may occupy multiple bins in a branch, but exactly one assignment per part per branch is `is_primary`; setting a new primary automatically demotes the old one.
2. The primary bin is what prints on pick slips, POS lookups, and putaway lists; overflow bins appear only when primary quantity is insufficient.
3. Sum of `qty_in_bin` across a part's bins must equal `qty_on_hand` in `stock_levels` for that branch; the nightly reconciliation flags mismatches for a spot count.
4. Scanning a bin barcode during a stock take loads the expected contents of that bin onto the count sheet.
5. A bin cannot be deactivated while any `qty_in_bin` > 0; parts must be moved out first.
6. Bin-to-bin moves are branch-internal and do not write stock ledger entries (total branch stock is unchanged); they are logged in a bin movement audit log instead.
7. Deleting a bin is only possible when it has never held stock; otherwise deactivate.
8. Bulk generation refuses to create codes that collide with existing `full_code` values in the branch.

## Edge Cases & Error Handling

- **Picker finds the primary bin empty** although system shows stock: pick screen offers "pick from overflow" and auto-raises a spot-count task on the primary bin.
- **Part physically found in an unassigned bin** during putaway: scanning part-then-bin prompts "create overflow assignment here?" rather than blocking.
- **Bin label damaged/unreadable**: storeman searches by code manually; reprint action on bin detail.
- **Two storemen move stock out of the same bin concurrently**: `qty_in_bin` update is guarded; the second move re-validates available bin quantity and fails with the fresh number.
- **Branch relayout** (shelving rearranged): bulk re-binning tool remaps assignments old-bin → new-bin in one operation, preserving quantities and audit history.
- **Move quantity exceeds `qty_in_bin`**: rejected; screen shows the bin's current quantity and suggests a spot count if the shelf disagrees.
- **Same part primary in two bins after a bad import**: integrity check surfaces it on the exceptions report; manager resolves by choosing one primary.
