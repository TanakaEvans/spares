# Coding Standards: Database

> Conventions for migrations, schema design, and Eloquent patterns.

---

## Naming Conventions

| Object | Convention | Example |
|--------|-----------|---------|
| Tables | `snake_case`, plural | `parts`, `stock_levels`, `purchase_orders` |
| Columns | `snake_case` | `part_number`, `is_active`, `qty_on_hand` |
| Primary key | `id` (bigIncrements) | `id` |
| Foreign keys | `{singular_relation}_id` | `customer_id`, `part_id`, `branch_id` |
| Boolean columns | `is_` prefix | `is_active`, `is_oem`, `is_posted` |
| Timestamps | Standard | `created_at`, `updated_at`, `deleted_at` |
| Pivot tables | Alphabetical, both singulars | `part_price_list` not `price_list_part` |
| Indexes | `{table}_{column}_index` | `parts_part_number_index` |
| Unique constraints | `{table}_{column}_unique` | `parts_part_number_unique` |
| Foreign key constraint | `{table}_{column}_foreign` | Auto-generated by Laravel |

## Standard Column Patterns

### All Business Entity Tables Must Have
```php
$table->id();
// ... business columns ...
$table->timestamps();      // created_at, updated_at
$table->softDeletes();     // deleted_at — for audit trail
```

### Monetary Values
```php
// Always decimal(15,2) for monetary values
// 15 total digits, 2 decimal places — handles values up to 9,999,999,999,999.99
$table->decimal('amount', 15, 2)->default(0);
$table->decimal('unit_price', 15, 2);
$table->decimal('credit_limit', 15, 2)->default(0);
```

### Quantities
```php
// decimal(10,2) for stock quantities (allows fractional units for fluids, etc.)
$table->decimal('qty_on_hand', 10, 2)->default(0);
$table->decimal('qty_ordered', 10, 2);

// int for counts that are always whole numbers
$table->integer('odometer')->nullable();
```

### Percentages
```php
$table->decimal('discount_pct', 5, 2)->default(0);  // max 999.99%
$table->decimal('vat_rate', 5, 2)->default(15.00);
```

### Exchange Rates
```php
$table->decimal('exchange_rate', 15, 6)->default(1);  // 6 decimal places for precision
```

### Status Columns
Use `string` with a database CHECK constraint or just rely on application validation. Avoid MySQL `enum` — it's painful to migrate.
```php
$table->string('status', 20)->default('draft');
// Document allowed values in code comments and in the module doc, not in the DB
```

### JSON Columns
```php
$table->json('parameters')->nullable();
// Cast in model: protected $casts = ['parameters' => 'array'];
```

## Migration Patterns

### Creating a Table
```php
public function up(): void
{
    Schema::create('parts', function (Blueprint $table) {
        $table->id();
        $table->string('part_number', 50)->unique();
        $table->string('oem_number', 100)->nullable();
        $table->string('description', 255);
        $table->string('short_description', 100)->nullable();
        $table->foreignId('category_id')->constrained('part_categories');
        $table->foreignId('brand_id')->constrained('part_brands');
        $table->foreignId('unit_of_measure_id')->constrained('units_of_measure');
        $table->string('barcode_ean', 20)->nullable()->unique();
        $table->decimal('weight_kg', 8, 3)->nullable();
        $table->boolean('is_oem')->default(false);
        $table->boolean('is_active')->default(true);
        $table->text('notes')->nullable();
        $table->timestamps();
        $table->softDeletes();

        // Indexes for frequent search columns
        $table->index('part_number');
        $table->index('oem_number');
        $table->index(['category_id', 'is_active']);
    });
}

public function down(): void
{
    Schema::dropIfExists('parts');
}
```

### Adding Columns (never modify existing migrations)
```php
// Create a NEW migration for schema changes
public function up(): void
{
    Schema::table('parts', function (Blueprint $table) {
        $table->string('barcode_code128', 50)->nullable()->after('barcode_ean');
    });
}

public function down(): void
{
    Schema::table('parts', function (Blueprint $table) {
        $table->dropColumn('barcode_code128');
    });
}
```

### Foreign Key Conventions
```php
// Constrained FK (hard reference, with cascade)
$table->foreignId('customer_id')->constrained('customers');

// Nullable FK (soft reference)
$table->foreignId('approved_by')->nullable()->constrained('users');

// FK with cascade delete
$table->foreignId('job_id')->constrained('job_cards')->cascadeOnDelete();

// FK with set null on delete
$table->foreignId('salesperson_id')->nullable()->constrained('users')->nullOnDelete();
```

### Pivot Tables
```php
Schema::create('part_price_list', function (Blueprint $table) {
    $table->id();
    $table->foreignId('part_id')->constrained()->cascadeOnDelete();
    $table->foreignId('price_list_id')->constrained()->cascadeOnDelete();
    $table->decimal('price', 15, 2);
    $table->decimal('discount_pct', 5, 2)->default(0);
    $table->timestamps();

    $table->unique(['part_id', 'price_list_id']);  // Prevent duplicates
});
```

## Indexing Strategy

Index columns that are:
- Foreign keys (always)
- Frequently searched/filtered (`part_number`, `registration`, `customer_number`)
- Frequently sorted (`created_at`, `document_date`)
- Used in WHERE clauses with high selectivity

```php
// Single column index
$table->index('part_number');

// Composite index (order matters — put the most selective first)
$table->index(['branch_id', 'is_active', 'part_number']);

// Unique index
$table->unique(['part_id', 'branch_id']);
```

**Do NOT index:**
- Boolean columns (too low selectivity)
- Short text columns with few distinct values
- Columns only used in SELECT (not WHERE/ORDER BY)

## Soft Deletes

All business entities use `SoftDeletes`. This provides:
- An audit trail of what was deleted
- Ability to restore accidentally deleted records
- Referential integrity (related records don't break)

```php
// In migration
$table->softDeletes();

// In model
use SoftDeletes;

// Query all including deleted
Part::withTrashed()->get();

// Query only deleted
Part::onlyTrashed()->get();

// Restore
$part->restore();

// Permanent delete (use only during cleanup, never for user-triggered delete)
$part->forceDelete();
```

**Business Rule**: Never permanently delete records that have financial transactions, stock movements, or are referenced by other records. Block the deletion at the service layer with a descriptive error message.

## Seeders

### Structure
```
Modules/InventoryManagement/database/seeders/
  InventoryManagementDatabaseSeeder.php  ← Orchestrates all seeders
  PartCategorySeeder.php                 ← Seeds category tree
  PartBrandSeeder.php                    ← Seeds common brands

Modules/VehicleReference/database/seeders/
  VehicleReferenceDatabaseSeeder.php
  VehicleMakeSeeder.php                  ← Seeds ~30 common makes
  EngineCodeSeeder.php                   ← Seeds common engine codes
```

### Seeder Pattern
```php
class PartCategorySeeder extends Seeder
{
    public function run(): void
    {
        $categories = [
            ['name' => 'Engine Parts', 'code' => 'ENG', 'parent_id' => null],
            ['name' => 'Filters', 'code' => 'ENG-FLT', 'parent_id' => ...],
            // ...
        ];

        foreach ($categories as $category) {
            PartCategory::updateOrCreate(
                ['code' => $category['code']],  // Idempotent — safe to re-run
                $category
            );
        }
    }
}
```

Use `updateOrCreate` not `create` in seeders — makes them idempotent and safe to re-run.

## Query Performance Rules

1. **Never load all records**: Always paginate or limit.
   ```php
   // ❌
   Part::all();
   
   // ✅
   Part::paginate(25);
   Part::limit(100)->get();
   ```

2. **Always eager load**: Specify relationships to prevent N+1.
   ```php
   // ❌ N+1: fires 1 + N queries
   Part::all()->map(fn($p) => $p->category->name);
   
   // ✅ 2 queries
   Part::with('category')->get()->map(fn($p) => $p->category->name);
   ```

3. **Select only needed columns**: Especially for dropdowns and lookups.
   ```php
   PartCategory::active()->get(['id', 'name', 'code']); // Don't load all columns for a select box
   ```

4. **Use `whereHas` for filtering by relationship**:
   ```php
   Part::whereHas('fitments', fn($q) =>
       $q->where('vehicle_make_id', $makeId)
         ->where('year_from', '<=', $year)
         ->where(fn($q2) => $q2->whereNull('year_to')->orWhere('year_to', '>=', $year))
   )->get();
   ```

5. **Use database-level aggregations**, not PHP:
   ```php
   // ❌
   StockLedger::where('part_id', $id)->get()->sum('qty');
   
   // ✅
   StockLedger::where('part_id', $id)->sum('qty');
   ```

## Cost Method: AVCO (Average Cost)

The system uses **Average Cost (AVCO)** for inventory valuation:

```
New Average Cost = (Current Stock Value + New Receipt Value) / (Current Qty + New Receipt Qty)
```

This is updated in the `StockLedgerService` whenever new stock is received (GRN). The `unit_cost` stored on each `stock_ledger` entry reflects the AVCO at the time of the movement.

An alternative is **FIFO** (First In, First Out). This is more accurate but requires batch-level cost tracking. Start with AVCO and add FIFO support later if required by an accountant.

## Migrations Naming & Order

Module migrations are ordered by the sequence number within the `database/migrations` folder. Use descriptive, verb-first names:

```
2026_01_01_000001_create_vehicle_makes_table.php
2026_01_01_000002_create_vehicle_models_table.php
2026_01_01_000003_create_vehicle_variants_table.php
2026_01_01_000004_create_parts_table.php
2026_01_01_000005_create_part_categories_table.php
2026_01_01_000006_create_stock_levels_table.php
2026_01_01_000007_create_stock_ledger_table.php
2026_01_02_000001_add_barcode_code128_to_parts_table.php  ← Later additions
```

Migration dependencies: if Table B has a FK to Table A, Table A's migration must run first.
