# POS Hardware & Printing

> The physical kit at the counter and how the software talks to it. Ignoring this until go-live week is the classic ERP rollout failure.

---

## Recommended Counter Kit (per till)

| Item | Spec | Notes |
|------|------|-------|
| PC / terminal | Any modern browser machine, 8GB RAM | The app is a web app — no special client |
| Barcode scanner | **USB HID, 2D** (reads EAN-13, Code128, QR) | HID = acts as a keyboard, zero drivers, works everywhere. 2D future-proofs for QR bin/job labels |
| Receipt printer | **80mm thermal, ESC/POS**, USB or Ethernet | Epson TM-T20 class or compatible clones |
| Cash drawer | RJ11, kicked by the receipt printer | Standard "print → drawer opens" wiring |
| A4 printer | Any network laser | Tax invoices, statements, POs, picking slips |
| Label printer (warehouse) | Thermal label, 40×30mm labels | Part/bin barcode labels |
| UPS | Per till + per server/router | Non-negotiable in ZW/SA — see resilience doc |

Warehouse/workshop extras: Android tablet (stock takes, job board), Bluetooth 2D scanner.

## How printing works (browser app → hardware)

| Path | Used for | How |
|------|----------|-----|
| **A: Browser print of PDF** | A4 documents | DomPDF renders; browser print dialog or silent-print via kiosk flag. Simple, works day one |
| **B: Direct ESC/POS via local print agent** | 80mm receipts + drawer kick | A tiny local agent (e.g. a Node/Go service or open-source WebSocket print server) on the till PC receives raw ESC/POS from the web app (`localhost` WebSocket) and pushes to the printer — instant, silent, opens drawer. **Recommended for POS** |
| **C: Browser print of 80mm HTML** | Fallback receipts | The thermal Blade template printed to the thermal driver. Slower, shows dialog — fallback only |

Implementation notes:
- `ReceiptPrinterService` (frontend lib) abstracts B-with-C-fallback; per-till printer config lives in the Configuration Centre (per branch → per till: printer name/IP, drawer kick on/off, receipt copies).
- Receipt template = 80mm Blade partial using the shared [document identity block](../configuration-centre.md) (compact variant: logo optional, company + branch + VAT no + rate line).
- Printing never blocks the sale (UI rule 8): fire-and-forget with retry toast.

## Barcode & label printing

- Internal Code128 labels generated by the app (`picqer/php-barcode-generator` — free) as part of the label Blade templates: **part label** (number, description, barcode, price optional), **bin label** (bin code + barcode), **GRN label** (part + batch + date).
- Batch printing: select N parts → "Print labels" → PDF sheet sized for the label printer.

## Scanner behaviour contract

- Scanners configured with **Enter suffix** (factory default) — the app's search inputs treat Enter as "lookup now" ([ui-rules.md](../design/ui-rules.md) §2).
- All barcode-bearing screens keep a scan target focused at rest: POS search, GRN receive line, stock-take bin field, job-card part add.
- A scanned code is looked up across: `barcode_ean` → `barcode_code128` → `part_number` → cross-references, in that order.

## Go-live checklist (per branch)
```
□ Tills: scanner scans a known EAN into Notepad (HID sanity test)
□ Receipt printer prints test page from agent; drawer kicks
□ Per-till printer config saved in Configuration Centre
□ A4 printer reachable from all counter PCs
□ Label printer calibrated; one shelf relabelled as pilot
□ UPS runtime tested ≥ 15 min under load
```
